1. 한 문장 문제 정의

공장 CCTV는 평상시 PPE 미착용이나 소화기·비상구 앞 이상을 사람이 계속 지켜보기 어렵고, 화재 발생 시에도 경보가 늦거나 경보 이후 각 작업자가 위험구역에 얼마나 오래 머무는지를 관리자가 즉시 파악하기 어렵다.

2. 제안 배경

2-1. 기존 화재 대응의 구조

(평상시) 사람이 직접 순찰하며 PPE·소화기 상태 확인 — 인력·시간 한계로 상시성 부족 → 화재감지기 작동 또는 육안 발견 → 경종·시각경보·비상방송 → 작업자 대피 → 집결지에서 수동 인원 확인 → 미확인자가 있으면 관리자·동료에게 질문 → CCTV를 되돌려 마지막 위치 확인

공백은 두 군데에 있다. 첫째, "평상시 위험 요소가 방치되는 것"과 "누군가 발견하는 것" 사이. 둘째, "화재가 발생했다는 사실을 알리는 것"과 "경보 이후 각 작업자 상태를 파악하는 것" 사이다.

2-2. 기존 방식의 한계

현재 방식현장 한계
순찰로 PPE·소화기 상태 확인순찰 간격 사이의 공백은 방치될 수 있음
화재감지기(열/연기 센서) 의존초기 미세 연기·화염을 놓치거나 오탐이 잦을 수 있음
출근명부·출입기록으로 재실자 확인이미 퇴근하거나 일시 외출한 사람이 포함될 수 있음
집결지에서 이름을 부르며 확인소음, 혼란, 부상, 언어 차이로 확인이 지연될 수 있음
관리자가 CCTV를 직접 재생여러 카메라의 과거 영상을 짧은 시간 안에 검토하기 어려움
카메라에서 사람이 사라지면 판단 불가대피, 가림, 사각지대 이동을 구분하기 어려움

3. 서비스 정의

3-1. 정식 주제명

RGB CCTV 기반 평상시 안전 예방 및 화재경보 이후 작업자 관측 지속시간 확인 시스템

3-2. 서비스 소개

LastSight AI는 기존 CCTV 영상을 활용해 평상시에는 PPE 미착용과 관리구역(소화기·전기패널·비상구) 이상을 상시 감시하고, 비상시에는 화재/연기를 자동 탐지해 경보를 트리거한 뒤 각 작업자가 지금도 관측되고 있는지·얼마나 오래 관측되고 있는지를 추적하는 통합 산업안전 서비스이다. 카메라 시야가 출구 바깥까지 잡지 못하는 현실적 제약 때문에 "출구를 통과했는지" 자체는 판정하지 않는다.

상태정의
관측중 inside_observed현재 관측되고 있으며, 화재경보 후 임계시간(기본 5분) 이내
장기체류경고 prolonged_presence화재경보 후 임계시간을 넘도록 계속 관측됨 — 확인 필요 신호
관측안됨 tracking_lost현재 관측되지 않음 — 안전/위험 어느 쪽도 확정하지 않고 마지막 위치·시각만 제공
카메라확인불가 camera_failure영상 입력 자체가 중단되어 판단 불가

3-3. 핵심 가치

화재 발생 사실을 알리는 데서 그치지 않고, 평상시에는 위험 요소를 상시 감시하고 화재 이후에는 관리자가 여러 CCTV를 직접 되돌려보는 시간을 줄여 확인이 필요한 사람과 구역을 빠르게 우선순위화한다.

5. 주제의 경쟁력

5-1. 문제 재정의의 차별성

LastSight AI는 화재·연기 탐지, PPE 감지 같은 단일 기능에 머무르지 않고, 평상시와 비상시 두 축의 사건 흐름을 연결한다.

[평상시] 사람·PPE 탐지 → 착용 판정 → 관리구역 변화 감지 → 이상 경고 [비상시] 화재/연기 탐지 → 경보 자동 트리거 → 작업자 추적 → 관측 지속시간 판정 → 장기체류 시 ZERO 2차 확인 → 확인 우선순위 산정 → 구조 브리핑 카드 생성 → (사후) 사고 리플레이

5-2. 공모전 평가와의 연결

6. 서비스 범위와 안전한 표현

6-1. 시스템이 판단하는 것

  • CCTV 화면에 보이는 사람과 임시 추적 ID
  • 작업자가 위치한 카메라·구역
  • PPE(안전모·안전조끼) 착용 여부
  • 관리구역(소화기·전기패널·비상구)의 기준 사진 대비 변화 여부
  • 화재/연기 여부와 경보 트리거
  • 화재경보 후 관측 지속 여부·지속시간
  • 확인이 필요한 작업자·구역의 우선순위
  • 마지막 관측 위치·시각
  • 제한된 보호구·복장 정보

6-2. 시스템이 판단하지 않는 것

  • 공장 전체의 정확한 총인원
  • CCTV가 없는 공간의 재실 여부
  • 작업자가 출구를 통과했는지 여부(카메라가 문 바깥을 못 보는 경우가 현실적으로 흔해 판정 대상에서 제외)
  • 관측이 끊긴 작업자가 실제로 안전한지 위험한지
  • 얼굴 기반 신원·국적·인종·성별·나이·체형
  • AI 단독 전원 안전·전원 대피 완료 선언
핵심 표현 원칙: "잔류자를 확정한다"가 아니라 "CCTV 관측 범위 내에서 관측/미관측 상태를 분류하는 보조 시스템"이라고 설명한다.

7. 전체 서비스 작동 흐름

1단계. 평상시 모니터링

  • CCTV 영상에서 사람·PPE(안전모·조끼)를 상시 탐지한다.
  • head+helmet IoU 기반으로 안전모 착용 여부를 기하학적으로 판정한다(색상 편향에 덜 취약).
  • 등록된 관리구역(소화기·전기패널·비상구)의 현재 화면을 기준 사진과 SSIM으로 비교해 변화를 감지한다. 사람이 구역과 겹친 프레임은 판정에서 제외한다.
  • 변화가 15분 이상 지속되면 이상으로 확정하고 대시보드에 경고한다.
  • 이름·사번·얼굴 정보와 연결하지 않는다.

2단계. 화재/연기 자동 탐지 및 경보 트리거

  • fire/smoke 탐지 결과가 최근 프레임의 일정 비율 이상 임계값을 넘으면 자동으로 화재경보를 발생시킨다(단발성 오탐 방지).
  • 관리자 수동 입력은 자동 탐지를 놓치는 경우를 위한 보조 오버라이드로 유지한다.
  • 화재경보 발생 시각·구역을 append-only 로그로 기록한다.

3단계. 다국어·시각 대피 안내

사업장에서 사전에 등록한 주요 언어를 동시에 출력하고, 얼굴을 보고 국적이나 사용할 언어를 추정하지 않는다.

4단계. 화재경보 이후 관측 지속시간 추적

  • 각 작업자가 지금도 관측되고 있는가
  • 관측되고 있다면 화재경보 후 얼마나 오래(기본 5분 임계값) 지속되고 있는가
  • 관측이 끊긴 경우, 왜 끊겼는지(대피/사각지대/장애물) 추측하지 않고 마지막 위치·시각만 기록한다

5단계. 작업자 상태 분류

상태판정 기준화면 표시

6단계. 결정적 순간 2차 확인

장기체류경고 또는 관리구역 이상 전환 시점에만, ZERO에 우려 상황 문구(예: "쓰러진 사람", "소화기를 가리는 박스")를 동시에 프롬프트로 던져 걸린 것들로 짧은 상황 설명을 자동 생성한다. 평소엔 가벼운 감지만 하다가 진짜 확인이 필요한 순간에만 추가 확인을 하는 이원화 구조다.

7단계. 확인 우선순위 산정(트리아지)

장기체류경고·관측안됨 작업자가 여럿이면, 지속시간·화재구역과의 거리·탐지 신뢰도를 explainable하게 합산해 "누구부터 확인할지" 순위를 매긴다. 위험도 확정이 아니라 확인 인력 투입 순서에 대한 참고 정보다.

8단계. 마지막 관측 정보 저장 및 참조 프레임 선택

  • 마지막 탐지 프레임과 가장 선명한 참조 이미지
  • 마지막 관측 카메라·구역·시각
  • 탐지 신뢰도·시야 확보 여부(정보가 추정치임을 드러내기 위함)

9단계. 구조 브리핑 카드 생성

노란색 안전모와 주황색 안전조끼, 회색 상의를 착용한 작업자입니다. 화재경보 후 7분째 B구역에서 계속 관측되고 있습니다(확인 필요). 2차 확인 결과: 특별한 우려 요소는 발견되지 않았습니다.

10단계. 관리자 검토 및 사고 리플레이

  • AI가 생성한 구조카드·상태는 관리자가 확인한다.
  • 공모전 MVP에서는 소방기관 시스템으로 자동 전송하지 않는다.
  • 사고 이후에는 화재경보·작업자 상태·관리구역 상태 변화 로그를 시간순으로 병합한 사고 리플레이 타임라인으로 특정 시각의 상태를 재구성해 감사·훈련에 활용할 수 있다.

9. Superb AI 플랫폼 활용 계획

Step 1. 데이터 선별

  • 자체 촬영 영상 검토(person/helmet/vest + 추적·관측지속시간 판정 테스트용)
  • 공개 데이터셋 라이선스·클래스 정의 확인 후 채택(CC BY 4.0 등)
  • fire/smoke는 자체 촬영 대신 공개 데이터셋 활용(실제 발화 불가)

Step 2. 데이터 구축 및 라벨링

  • PPE 프로젝트와 Fire/Smoke 프로젝트를 목적이 달라 별도로 분리 생성
  • 클래스 정의(4-1) 및 속성 등록
  • SDK로 라벨 반입 후 스냅샷 생성 — 학습은 항상 스냅샷 기준

Step 3. 모델 학습 및 실험

  • PPE: rf-detr-nano로 베이스라인 → 연기 증강 → 뛰는 자세 보강 → 색상 편향 대응 → no_helmet/no_vest 보조 클래스 순으로 반복 개선
  • Fire/Smoke: segmentation 시도 → 데이터 다양성·라벨 불일치로 실패 진단 → detection(rf-detr-nano)으로 전환해 해결
  • ZERO 파운데이션 모델과 커스텀 모델의 실사용 성능을 비교해 최종 배포 판단

Step 4. 서비스 구현 및 데모

  • 추론 결과와 ByteTrack 경량 구현 연결
  • 관측 지속시간 규칙 엔진 구현
  • 구조카드·대시보드(평상시/비상시 모드)·사고 리플레이 제작
  • 실제 영상 기반 시연

False All-Clear Rate확인이 필요한 상황인데 시스템이 이를 놓치거나 위험 신호 없음으로 표시하는 비율
관리구역 이상 탐지 지연시간실제 변화 발생부터 이상 확정까지 걸린 시간

가장 중요한 안전 지표: False All-Clear Rate. 확인이 필요한 상황인데 시스템이 이를 놓치는 경우를 최소화한다. AI가 "전원 안전"을 단독으로 확정하는 로직은 만들지 않는다.

15. 데모 시나리오

  1. 작업자 여러 명이 공장 내부에서 평상시처럼 작업한다 — 대시보드는 평상시 모드(PPE 준수율, 관리구역 상태)를 표시한다.
  2. 한 명이 안전모를 벗는다 — PPE 미착용이 즉시 감지된다.
  3. 연기가 감지되어 화재경보가 자동으로 트리거된다 — 대시보드가 비상시 모드로 자동 전환된다.
  4. 전광판과 음성으로 사용 가능한 출구를 다국어 안내한다.
  5. 대부분의 작업자는 화면에서 사라진다(관측안됨으로 표시, 안전/위험 확정하지 않음).
  6. 한 명이 화재경보 후에도 같은 구역에서 계속 관측된다 — 임계시간(5분, 데모에서는 축소된 값)을 넘기면 장기체류경고로 전환된다.
  7. 장기체류경고 전환 순간 ZERO 2차 확인이 자동으로 호출되어 우려 상황을 짧게 요약한다.
  8. 여러 명이 동시에 장기체류경고 상태면, 확인 우선순위 목록이 지속시간·화재구역과의 거리로 정렬되어 표시된다.
  9. 가장 선명한 참조 이미지를 선택해 구조카드를 만든다.
  10. 관리자가 사고 리플레이 타임라인으로 화재경보 발생부터 지금까지의 전체 흐름을 다시 확인한다.

19. 서비스 한계

  • CCTV가 설치되지 않은 구역은 분석할 수 없다.
  • 화장실·탈의실처럼 촬영이 제한된 공간의 재실자는 확인할 수 없다.
  • 심한 연기·정전·카메라 파손 이후 현재 위치는 알 수 없다.
  • 동일한 복장을 입은 여러 사람이 교차하면 추적 ID가 바뀔 수 있다.
  • 마지막 관측 위치는 현재 위치가 아니다.
  • 커스텀 fire/smoke 모델은 학습 데이터가 8개 영상 클립뿐이라 낯선 장면에서는 검증 지표만큼의 성능을 보장하지 않는다(그래서 서비스 기본값은 ZERO를 사용).
  • ZERO는 플랫폼이 스케줄에 따라 켜고 끄는 공유 엔드포인트라 워밍업 중 호출이 실패할 수 있다.
  • AI 결과만으로 소방대원의 진입 여부나 수색 경로를 결정해서는 안 된다.
  • 실제 화재영상이 아닌 연출·합성 데이터를 사용하므로 현장 성능은 별도 검증이 필요하다.

23. 최종 발표 구성

문제

평상시 위험 요소는 상시 감시가 어렵고, 화재경보가 울려도 이후 각 작업자의 상태를 자동으로 확인하기 어렵습니다.

해결책

LastSight AI는 CCTV로 PPE·관리구역을 상시 감시하고, 화재/연기를 자동 탐지해 경보를 트리거한 뒤 관측 지속시간을 기준으로 확인이 필요한 대상을 알려줍니다.

안전 원칙

관측이 끊긴 작업자를 대피 완료로, 계속 관측된다고 위험 확정으로 간주하지 않습니다. AI는 전원 안전을 단독 선언하지 않습니다.

차별점

화재 탐지에서 그치지 않고, 화재경보 이후 대피 이행까지 끝까지 확인하는 AI입니다.

24. 심사위원 예상 질문과 답변

Q1. 카메라에서 사람이 사라지면 대피한 것으로 잘못 판단하지 않나요?

아니다. 이 시스템은 출구 통과 여부 자체를 판정하지 않는다 — 카메라가 문 바깥까지 못 보는 경우가 현실적으로 흔해, "통과 확인"이 구조적으로 성립하기 어렵다는 걸 검증하고 폐기했다. 대신 관측이 끊기면 tracking_lost로만 표시하고 안전/위험을 확정하지 않는다.

Q2. 잔류 인원 수를 정확하게 알 수 있나요?

공장 전체 잔류 인원을 확정하는 시스템은 아니다. CCTV 관측 범위 내에서 관측/미관측 상태를 분류하는 보조 시스템이다.

Q3. 왜 자체 학습한 fire/smoke 모델 대신 ZERO를 쓰나요?

커스텀 모델은 검증 지표(F1 0.897)는 좋았지만, 학습 데이터가 영상 8개 클립뿐이라 실사용에서는 훨씬 넓은 범위로 학습된 ZERO보다 일반화가 떨어지는 것을 직접 확인했다. 검증 지표만 믿지 않고 데이터 기반으로 서비스 배포를 판단한 사례다. 배포는 그대로 남겨 언제든 전환 가능하다.

Q4. 동일한 작업복을 입은 작업자를 어떻게 구분하나요?

복장만으로 동일인을 확정하지 않는다. 객체 추적의 임시 ID를 사용하며, IoU를 주 기준으로 박스 크기 유사도를 보조 기준으로 삼아 IDF1과 ID Switch를 평가한다.

Q5. 왜 얼굴인식을 사용하지 않나요?

신원 자동식별이 반드시 필요하지 않고 개인정보 부담이 크기 때문이다. 사건 내 임시 ID와 참조 이미지, 보호구·복장 정보만 제공한다.

Q6. 소화기 상태는 어떻게 확인하나요? 별도 모델을 학습했나요?

아니다. 실제 CCTV는 각도·거리·조명이 제각각이라 정면 사진 위주의 공개 데이터셋으로 학습한 탐지기가 잘 안 맞을 위험이 컸다. 대신 소화기·전기패널·비상구를 "관리구역"으로 등록하고, 기준 사진 대비 SSIM 변화 감지로 이상을 판단한다 — 신규 데이터셋·학습이 필요 없다.

Q7. Superb AI 플랫폼은 어디에 사용하나요?

데이터셋·프로젝트 생성, 클래스 스키마 설계, 라벨 반입, 스냅샷 관리, 모델 학습, ZERO 파운데이션 모델 호출, 모델 배포까지 SDK로 전 과정을 코드화해 재현 가능한 파이프라인으로 구축했다.

25. 최종 요약

질문답변
무엇을 해결하는가?평상시 위험 요소 상시 감시의 공백과, 화재경보 이후 작업자 상태를 자동으로 확인하기 어려운 문제
Vision AI가 필요한가?화재/연기 자동 탐지, 작업자·PPE 탐지·추적, 관리구역 변화 감지, 2차 확인·트리아지에 필요
기존 화재설비와 겹치는가?기존 설비는 화재 감지와 경보, LastSight AI는 평상시 예방과 경보 이후 관측 지속시간 확인·구조정보를 제공
다국어 기능은 어떻게 연결되는가?사업장 주요 언어와 픽토그램으로 대피를 안내하고 이후 관측 지속시간을 확인
가장 중요한 안전설계는?관측이 끊긴 작업자를 대피 완료로, 계속 관측된다고 위험 확정으로 간주하지 않음 — AI는 전원 안전을 단독 선언하지 않음

최종 기획 문장
LastSight AI는 평상시에는 PPE·관리구역을 상시 감시하고, 화재 발생 시 다국어와 시각정보로 대피를 안내하며 화재/연기를 자동 탐지해 경보를 트리거한다. 경보 이후에는 각 작업자가 얼마나 오래 관측되고 있는지를 기준으로 확인이 필요한 대상의 우선순위를 매기고, 필요한 순간에만 추가 확인을 거쳐 구조 브리핑 카드와 사고 리플레이를 제공함으로써 현장 관리자의 대응을 지원한다.

# BDAI (Superb AI) 플랫폼 사용 매뉴얼 학습 정리

> 출처: https://guide.bdai.superb-ai.com/ko/ (전체 39개 하위 페이지)

## 플랫폼 개요

BDAI는 데이터 라벨링부터 모델 학습·진단·배포까지, AI 개발 과정을 한 곳에서 잇는 플랫폼이다. 매뉴얼은 작업 흐름, 즉 데이터에서 모델로 이어지는 순서(데이터 준비 → 프로젝트 구성 → 라벨링 → 검수 → 스냅샷 → 모델 학습 → 배포·활용 → 테넌트 운영)대로 구성되어 있다.

**핵심 용어**

- **테넌트(Tenant)**: 조직 단위.
- **데이터셋(Dataset)**: 원본을 모아 두는 가장 큰 단위.
- **에셋(Asset)**: 낱개 파일 하나.
- **프로젝트(Project)**: 데이터셋 위에 얹는 라벨링 작업.
- **스키마(Schema)**: 무엇을 라벨링할지 정의(객체 클래스, 분류 항목, 속성).
- **스냅샷(Snapshot)**: 그 시점까지의 라벨을 그대로 담아 둔 것.
- **학습 실행(Training Run)**: 스냅샷으로 모델을 학습하는 한 번의 작업.
- **모델(Model)**: 학습이 끝난 결과물.
- **배포(Deployment)**: 학습한 모델을 실제로 돌려 쓸 수 있게 띄워 두는 것.
- **비교(Compare)·체험(Try)**: 학습한 모델을 이미지에 돌려 결과를 확인. 체험은 모델 하나, 비교는 여러 모델을 나란히 확인.

**역할과 화면**

같은 사이클이라도 역할별로 맡는 단계와 열리는 화면(제품 역할)이 다르다.

| 역할 | 하는 일 | 주로 보는 화면 |
|---|---|---|
| labeler | 작업 큐에서 받아 캔버스에서 그리고 제출 | 프로젝트 |
| reviewer | 리뷰 큐에서 승인하거나 재작업으로 반려 | 프로젝트 |
| manager | 프로젝트·스키마·멤버·스냅샷·학습을 설정 | 프로젝트 |
| admin | 위 전부 + 모델·배포·비교까지 | 테넌트 |

읽는 순서 권장: 처음이라면 개념과 빠른 시작부터. 그다음 데이터 준비 → 배포까지 사이클을 순서대로. 혼자 작업한다면 협업 전용 단계(프로젝트 구성 일부, 검수)는 건너뛰어도 된다.

## 시작하기

### 소개 (핵심 개념)
위 "핵심 용어"·"역할과 화면" 내용 참고. 준비되면 빠른 시작에서 첫 데이터셋부터 첫 모델까지 따라가 볼 것을 권장.

### 홈 (테넌트 개요)
테넌트에 들어오면 처음 만나는 화면. 데이터에서 모델까지 이어지는 사이클을 한 화면에 요약.

- 맨 위 띠 = 파이프라인 현황: 데이터셋 → 스냅샷 → 학습된 모델 순으로 개수 표시. 학습 중이면 가운데 화살표에 "학습 중" 표시.
- 아래 세 칸: 진행 중인 프로젝트(라벨링 진행률) / 스냅샷 / 최근 학습된 모델(F1·배포 상태)을 최근 순으로 표시. 각 항목 클릭 시 해당 화면으로 이동.

### 빠른 시작: 첫 데이터셋부터 첫 모델까지
데이터 준비부터 배포까지 사이클을 한 번에 훑는 길. 화면 이동 구조(상단 탭·주소 구조)를 먼저 익히면 따라가기 쉬움.

1. **데이터 준비**: 데이터셋 만들기 → 업로드. 필요하면 임베딩으로 AI 검색 활성화.
2. **프로젝트 구성**: 데이터셋 위에 프로젝트 생성(고른 에셋이 작업 범위) → 스키마 정의 → 멤버 추가·작업 배정 방식 결정 → 가이드라인 작성.
3. **라벨링**: 라벨러가 작업 큐에서 받아 캔버스에서 라벨링 후 제출. 진행 상황은 라벨링 현황에서 확인.
4. **검수**: 리뷰어가 승인하거나 재작업으로 반려.
5. **스냅샷 만들기**: 지금까지 라벨을 그 시점 그대로 담음.
6. **모델 학습**: 스냅샷으로 학습 시작 → 모델 성능 지표로 품질 확인.
7. **배포와 활용**: 모델 배포 → 비교(여러 모델 나란히 확인, 모델 하나면 체험) → 자동 라벨링이 학습된 모델을 다음 데이터에 연결하며 사이클이 닫힘.

💡 무거운 작업 진행 상황은 요청 현황, 활동 이력은 활동 기록에서 확인.

### SDK·AI 연동
화면 밖에서도 데이터를 다룰 수 있음. 파이썬 SDK로 직접 코드를 짜거나, 코드를 쓰지 않는다면 AI 코딩 도구에 맡길 수 있음. 시작은 API 키 하나.

- **준비**: API 키 화면에서 키 발급(생성 시 한 번만 표시, 비밀번호처럼 취급).
- **파이썬 SDK**: `pip install superb-ai` 설치 후 `Client(tenant=..., api_key=...)`로 인증하면 데이터셋·라벨·스냅샷·학습을 코드로 조작 가능. 환경변수 `SUPERB_AI_TENANT` / `SUPERB_AI_API_KEY` 설정 시 `Client()`만 호출해도 됨.
- **AI 코딩 도구에 맡기기**: 내 컴퓨터에서 직접 코드를 짜고 실행할 수 있는 도구(브라우저 챗봇 불가)에 안내 지문을 붙여넣어 설치·연결까지 자동화 가능. 연결 후에는 자연어로 지시("이 폴더의 이미지를 데이터셋에 업로드해 줘" 등) 가능. 공식 SDK 문서: https://docs.bdai.superb-ai.com/

## 1. 데이터 준비

### 데이터셋 만들기
원본을 담을 데이터셋 생성. 데이터셋은 에셋을 묶는 가장 큰 단위.

- **데이터셋 목록**: 테넌트의 모든 데이터셋을 한곳에서 확인, 필터로 추림.
- **새 데이터셋**: 이름을 정하면 업로드로 이어짐.

### 업로드
데이터셋에 원본을 채우는 화면. 이미지나 폴더를 한꺼번에 드래그.

- **업로드 영역**: 드래그 또는 둘러보기로 파일 선택. 한 번에 올릴 수 있는 한도 안내.
- **업로드 중**: 위쪽에 전체 진행률, 오른쪽에 파일별 진행률. 다른 화면으로 이동해도 상단 바에서 계속 진행. "모두 취소"로 중단 가능.

### 임베딩
비슷한 이미지를 찾기 위해 미리 준비하는 작업. 만들어 두면 "이것과 비슷한 이미지 찾기" 기능 사용 가능.

- 버튼을 누르면 아직 준비되지 않은 이미지를 백그라운드에서 처리. 진행 상황 표시. 다시 눌러도 이미 처리한 이미지는 건너뜀. 양이 많으면 시간이 다소 소요.

## 2. 프로젝트 구성

### 프로젝트 만들기
데이터셋 위에 프로젝트를 얹음. 같은 자료를 용도별로(예: 사람 검출용/차량 검출용) 다르게 라벨링 가능. 생성은 2단계.

1. **기본 정보와 배정 방식**: 이름 필수. "에셋"은 기본적으로 데이터셋 전체, 일부만 원하면 에셋 리스트에서 선택. "배정 방식"은 자율 할당(라벨러가 스스로 가져감) 또는 매니저 배정(매니저가 직접 배정) 중 선택 — 이후 작업 배정에서 변경 가능.
2. **스키마 정의**: "객체 검출" 탭에서 "+ 객체"로 박스·폴리곤 클래스 생성 후 색·타입·속성 지정. "분류" 탭에서는 이미지 전체에 붙는 항목 생성. 클래스가 최소 하나는 있어야 생성 가능.

### 스키마
프로젝트에서 "무엇을 라벨링할지" 정의. 라벨러는 여기 정한 것만 그리고 고를 수 있음. 상단 탭이 객체 검출(개별 객체)과 분류(이미지 전체)로 구분.

- **객체 클래스 정의**: 클래스마다 이름·아이콘·색으로 모양(박스/폴리곤 등) 표시. "속성(Attribute)"은 객체에 딸린 세부 질문(예: person에 자세, 가림). "+ 객체"로 신규 추가.
- **클래스와 속성 편집**: 클래스 클릭 시 이름·색·어노테이션 타입(박스·폴리곤·폴리라인·키포인트) 및 속성 편집. 속성 입력 타입은 라디오(하나 선택)·체크박스(복수 선택)·자유 입력 텍스트. 라디오·체크박스는 옵션·기본값 설정, "필수" 설정 시 제출 전 반드시 채워야 함.
- **이미지 분류 항목**: 이미지 전체에 붙는 항목(예: 날씨) 생성. 라디오/체크박스/텍스트 타입 지원, "필수" 여부 설정 가능.

### 프로젝트 멤버
프로젝트에서 누가 어떤 역할을 맡는지 설정. 역할이 권한을 결정.

- **매니저**: 배정 방식·멤버·스키마 변경, 모든 에셋 리뷰 가능.
- **리뷰어**: 리뷰 큐 제출물 승인/반려만 가능(배정·스키마 편집 불가).
- **라벨러**: 배정받은 에셋만 라벨링(리뷰 권한 없음).
- **테넌트 관리자**: 목록 상단 고정 표시, 모든 프로젝트에서 매니저 권한 자동 보유. 새 멤버 추가는 테넌트 관리자만 가능.

### 작업 배정
작업을 라벨러에게 나눠주는 방식 결정.

- **자율 할당**: 라벨러가 미배정 작업을 스스로 가져가거나 보유 작업 이어감. 빠르지만 누가 무엇을 할지는 자율에 맡김.
- **매니저 배정**: 매니저가 각 작업 직접 배정. 손이 더 가지만 품질 관리·부하 분산 통제력 확보.

### 가이드라인
라벨러에게 공유할 작업 지침 작성 화면. 매니저가 정리하면 라벨러는 읽기 전용으로 확인.

- "작성"/"편집"으로 에디터 오픈, 툴바로 서식을 넣어 클래스 정의·예시·예외 처리 방법 정리. 이미지 드래그/붙여넣기 또는 데이터셋 에셋 선택으로 예시 삽입 가능. 저장 시 프로젝트의 모든 라벨러에게 읽기 전용 공유.

### 태그
프로젝트 안에서 에셋을 분류하는 태그(프로젝트 단위 어휘) 관리.

- 태그 생성 시 색·표시 이름 지정, 태그별 붙은 에셋 수 표시. "태그 잠금" 켜면 정해진 목록만 사용 가능(어휘 통제), 끄면 작업 중 새 태그 추가 가능(자동으로 목록에 추가). 태그는 에셋 목록 필터로 활용.

## 3. 라벨링

### 작업 큐
라벨러가 하루를 시작하는 화면. 할 일을 세 칸으로 구분.

- **재작업 필요**: 리뷰어가 돌려보낸 항목(반려 사유 표시).
- **이어서**: 중간에 멈춘 항목, 멈춘 자리에서 재개.
- **새 작업 시작**: 아직 손대지 않은 자료.
- 카드를 열면 해당 에셋의 캔버스로 바로 진입.

### 에디터 화면 안내
에셋을 열면 나오는 라벨링 에디터의 구성.

- **왼쪽 도구 레일**: 그리기 도구, 코멘트, 표시 설정. 맨 아래 버튼으로 "정보"·"코멘트" 패널(보기/리뷰 모드에서는 "변경 이력"도) 오픈.
- **가운데 캔버스**: 이미지를 보며 그리는 곳. 도형 선택 시 화면 아래 가운데 동작 바 표시.
- **오른쪽 작업 패널**: 위에서부터 "분류", "도형" 목록, 선택 도형 상세, 맨 아래 제출 푸터.
- **화면 맨 아래 상태줄**: 현재 도구 사용법, 확대율, 이미지 크기 상시 표시. 전체 단축키는 F1.
- **모드**: "보기"(읽기 전용, 누구나), "편집"(라벨링, 미할당 에셋이면 할당 여부 확인), "리뷰"(검수, 리뷰 권한 필요 시만 활성화).

### 라벨링 캔버스
객체를 실제로 표시하는 곳. 도구로 그리고 클래스를 붙인 뒤 체크리스트를 비우고 제출.

- 도구 레일에서 도구 선택 후 스키마에 정의된 클래스에 맞춰 그림.
- 작업 패널 "도형" 목록에서 확인, 도형 선택 후 클래스·속성 수정.
- 이미지 전체 질문은 패널 위쪽 "분류"에서 응답. 어노테이션은 자동 저장.
- 푸터 "체크리스트"로 제출 전 남은 항목 확인. 남은 항목 있는 채로 제출 시 무엇이 남았는지 먼저 안내. 제출하면 에셋이 리뷰 대기로 전환.

### 그리기 도구 고르기
도구마다 적합한 객체가 다름.

- **박스**: 윤곽이 단순한 객체(차량, 표지판)에 가장 빠름.
- **폴리곤**: 윤곽을 정확히 따야 할 때. 클릭으로 점을 이어 그림. 선택 시 하단 바에서 분할·합치기·점 추가 등 정리 동작 가능.
- **스마트 세그먼트**: 객체 클릭 시 윤곽 자동 추출, "점 편집"으로 다듬는 방식이 효율적.
- **키포인트/브러시**: 관절 등 점 구조, 경계가 흐린 영역 등 도형으로 그리기 어려운 대상.
- **표시 설정**: 채움 불투명도, 핸들 크기, 캔버스 라벨 표시 내용, 툴바 위치 등 화면 전용 설정(데이터에는 영향 없음).

### 에셋 분류 답하기
분류는 이미지 전체에 대한 질문(날씨, 시간대 등). 도형이 아니라 에셋 하나당 하나씩 응답.

📘 분류(classification)=에셋 전체 답, 속성(attribute)=도형 하나에 붙는 답(도형 선택 시 상세에서 입력).

- **분류 섹션**: 작업 패널 맨 위. 제목 줄 숫자=답한 개수, 미응답 필수 질문에는 빨간 Required 표시. 응답은 즉시 저장. 섹션 제목 클릭으로 접기, 가장자리 드래그로 높이 조절.
- **체크리스트로 누락 항목 찾기**: 푸터 "체크리스트" 클릭 시 오른쪽에 남은 항목 목록. 항목 클릭 시 해당 질문으로 이동. 모두 채우면 칩이 회색으로 바뀌고 제출 가능.

### 코멘트와 이슈
작업 중 궁금하거나 지적할 사항을 코멘트로 남김. 위치를 가질 수 있어 정확한 위치 전달 가능.

- **코멘트 달기**: 레일 "코멘트" 버튼 클릭 후 위치 선택 — "포인트"/"영역"(캔버스 특정 위치), "도형"(선택 도형에 부착, 도형 이동 시 함께 이동), "에셋"(위치 없이 이미지 전체).
- **스레드와 목록**: 캔버스 핀 클릭 시 스레드 오픈, 답글/해결 표시 가능. 스레드 머리의 목록 버튼으로 오른쪽 코멘트 목록 오픈(보던 스레드는 유지되고 목록에서 강조).

### 이슈
에셋을 두고 주고받은 코멘트·이슈가 모이는 곳. 리뷰어와 라벨러가 같은 화면 공유.

- 목록에서 항목을 열면 해당 에셋의 코멘트 스레드로 바로 이동. 반려 사유나 질문을 이어서 진행.

### 라벨링 현황 (에셋 보드)
프로젝트의 라벨링 진행 상황을 둘러보는 화면. 이미지 기준/객체 기준 두 가지 보기.

- **에셋 둘러보기(이미지 기준)**: 썸네일 격자, 지금까지 그려진 어노테이션이 겹쳐 표시. 검색·필터로 추림. 목록 보기로 전환 시 상태·담당자 등 열 형태로 확인 가능.
- **어노테이션 둘러보기(객체 기준)**: "어노테이션" 탭에서 객체 단위로 확인. 잘라낸 썸네일 + 클래스 이름 카드. 전체 개수 표시, 클래스 필터 가능. 카드 클릭 시 해당 캔버스로 진입.

### 라벨링 시간
라벨링에 소요된 시간 확인. 오늘/이번 주 합계 상단 표시.

- 기간을 바꿔가며 추세 확인. 팀 합계와 라벨러별·라벨별 분포도 함께 제공.

### 리뷰 큐

## 5. 스냅샷

### 스냅샷 만들기
라벨이 어느 정도 쌓이면 생성. 스냅샷은 그 시점까지의 라벨을 그대로 담은 것. 학습은 이 스냅샷으로 진행.

- **스냅샷 목록**: 만들어 둔 스냅샷을 상태와 함께 확인. 새로 생성하면 현재 라벨을 담아 학습에 사용 가능.
- **스냅샷 열어 보기**: 생성자·생성 시각, "스냅샷 에셋"·"스냅샷 클래스" 개수, 당시 스키마 확인 가능. "스냅샷 에셋" 탭에서 당시 데이터 조회, "익스포트"에서 COCO·YOLO·Superb Platform 형식으로 다운로드.

  ⚠️ 스냅샷은 한 번 만들면 바뀌지 않음. 이후 스키마·라벨을 수정해도 스냅샷은 그대로 유지되며, 학습은 항상 이 고정된 데이터를 사용.

- **스냅샷 에셋 둘러보기**: 그 시점 데이터를 읽기 전용으로 조회. 라이브 "라벨링 현황"과 화면은 동일하나 내용은 고정. 학습이 정확히 무엇을 보았는지 확인할 때 사용.

## 6. 모델 학습

### 모델 학습 시작
라벨 데이터에서 모델로 넘어가는 유일한 진입점. 매니저가 스냅샷을 선택해 학습 실행.

- **학습 기록**: 이 프로젝트에서 실행한 학습이 진행 상태와 함께 쌓임. 상단 버튼으로 신규 학습 시작.
- **학습 설정**: 학습에 사용할 스냅샷 선택 → 해당 시점 라벨로 모델 생성. 학습 완료 시 모델 레지스트리에 결과 등록.

### 모델 (모델 레지스트리)
테넌트의 모델이 모이는 곳. 학습 없이 바로 쓰는 기본 제공 모델과 직접 학습한 내 모델을 함께 확인.

- **기본 제공 모델**: ZERO, Gemini — 학습 없이 바로 사용 가능.
- **내 모델**: 학습한 모델이 성능과 함께 정리. 모델 클릭 시 성능 지표, "체험"(단일 모델 이미지 테스트), "배포", "설정" 탭 제공. 여러 모델 비교는 상단 "비교" 탭 사용.

### 모델 성능 지표
학습으로 만든 모델의 배포 적합성 및 약점 판단.

- 점수는 학습에 사용하지 않은 테스트 이미지 기준. 절대 등급이 아니라 런 간 비교, 약한 클래스 파악 용도.
- **요약 카드**: mAP@50(느슨한 기준, 박스 대략 위치)과 mAP(엄격한 기준, 정확한 위치). 둘의 차이가 크면 "객체는 찾지만 위치가 부정확"을 의미.
- **정밀도(Precision)·재현율(Recall)·F1**: 정밀도 높고 재현율 낮음=조심스러워 놓침 多, 반대=과탐지(오탐) 多. F1은 균형점. "권장 임계값"=F1 최고점의 신뢰도로, 자동 라벨링·비교의 기본값으로 적합.
- **클래스별 결과**: F1 낮은 클래스가 라벨 보강 후보. "테스트 인스턴스"가 적어 "데이터 부족" 표시된 경우 표본 부족을 의미하므로 데이터 증량 우선.
- **혼동 행렬(Confusion Matrix)**: 세로=실제, 가로=예측. "자주 혼동" 칩=가장 많이 섞인 클래스 쌍. "객체 없음" 열=미탐, 행=오탐. 자주 혼동되는 클래스는 가이드라인 명확화나 예시 보강으로 개선.

## 7. 배포·활용

### 배포 (엔드포인트)
학습한 모델을 실제로 쓸 수 있게 띄워 두는 곳. 켜 두면 이미지 예측 수신 가능, 다 쓰면 중지.

- 배포 준비 완료 시 예측 수신 가능. 코드에서 호출하는 API 스니펫 제공 — 복사해서 코드에서 바로 예측 호출.

### 배포 목록
띄워 둔 배포를 한곳에서 확인. 현재 실행 중인 모델과 비용 발생 여부 확인.

- 활성 배포가 상태와 함께 표시. 사용 종료 시 여기서 중지해 비용 절감.

### 비교 (플레이그라운드)
같은 이미지를 여러 학습 모델에 돌려 나란히 비교. 모델 하나만 볼 때는 해당 모델 페이지의 "체험" 탭 사용, 여러 개 비교 시 이 화면 사용.

- **모델 고르고 이미지 넣기**: 비교할(학습·배포된) 모델 다수 선택 후 이미지 입력. 결과는 모델별 칸으로 나란히 표시.
- **예측 결과 보기**: "실행" 클릭 시 각 모델이 예측 수행, 찾은 객체를 박스로 이미지 위에 표시. "신뢰도" 슬라이더로 약한 예측 필터링. 다수 모델 선택 시 같은 칸 배치로 나란히 비교.

### 자동 라벨링
배포한 모델로 새 에셋을 미리 라벨링해두는 기능. 학습 모델을 다음 데이터에 먼저 적용해 사이클을 닫는 단계. 예측 결과는 어노테이션으로 들어가며 사람이 검수.

- **모델·임계값·클래스 매핑**: 모델 선택 시 추가 설정 노출. "신뢰도 임계값" 미만 예측은 검수 대상 표시. 모델 클래스명이 우리 라벨과 다르면 "클래스 매핑"으로 연결. "에디터에서 라벨러가 자동 라벨링하도록 허용" 활성화 시 라벨러가 작업 중 모델 제안을 받을 수 있음.
- **검수까지 건너뛰기**: "고급" 옵션 "표시된 객체가 없으면 검수 건너뛰기" 활성화 시, 모든 객체가 임계값을 넘은 에셋은 검수 없이 바로 완료 처리.

  ⚠️ 건너뛴 결과는 사람이 보지 않으므로, 모델을 충분히 신뢰할 수 있을 때만 임계값을 높이고 활성화해야 함.

## 8. 테넌트 운영

### 일반
테넌트의 기본 정보를 보는 설정.

- **테넌트 정보**: 테넌트 이름·slug·내 역할 확인(이름·slug는 여기서 변경 불가). "테넌트 나가기"로 탈퇴 가능(계정·다른 테넌트에는 영향 없음). 관리자가 본인뿐이면 나갈 수 없음.

- 멤버 초대 및 테넌트 역할 변경. 관리자는 모든 프로젝트의 매니저 권한을 자동으로 보유.

### API 키
코드에서 API 호출 시 사용하는 키 관리.

- **API 키 관리**: 키 생성 후 외부 스크립트/파이프라인 인증에 사용. ❗ 키는 생성 시 한 번만 표시. 발급한 키의 활용법(파이썬 코드, AI 코딩 도구)은 SDK·AI 연동 참고.

### 활동 기록
테넌트 내 행위를 남기는 감사 로그. 관리자만 열람 가능.

- 라벨링·업로드·리뷰·배포 등의 행위가 시간순으로 쌓임. 필터로 좁혀 볼 수 있음.

## 참고

### 요청 현황
대량 삭제·익스포트·학습·자동 라벨링 등 무거운 작업은 백그라운드 요청으로 처리되며 여기서 진행 상황 추적. 진행 중인 요청이 있으면 상단 바에 표시.

- **백그라운드 요청 모니터**: 진행 중·완료·실패 요청이 한곳에 모임.

### 화면 이동 구조
화면은 세 겹으로 이동. 헷갈릴 때 이 구조를 떠올리면 됨.

- **상단 탭(테넌트)**: 개요·데이터셋 목록·모델·요청 현황·활동 기록·설정. 이 중 모델·활동 기록·설정은 관리자에게만 표시. 비교·배포 목록은 모델 안의 탭.
- **섹션 탭**: 데이터셋/프로젝트 진입 시 그 안의 탭으로 전환. 데이터셋 탭 중 프로젝트 목록은 전체 공개, 에셋·업로드·설정은 관리자 전용. 프로젝트 탭은 역할별로 다름.
- **설정 사이드바**: 설정 내에서 일반·멤버·스키마 등 그룹으로 구분.
- 왼쪽 위 브레드크럼이 테넌트 › 데이터셋 › 프로젝트 순으로 현재 위치 표시(스냅샷·학습 실행 진입 시 칩 추가).

**역할별 프로젝트 탭**: 이슈·가이드라인·라벨링 시간·학습은 공통. 라벨러=작업 큐, 리뷰어=에셋 목록(리뷰 대상), 매니저=라벨러·리뷰어 화면 + 어노테이션·스냅샷·설정 등 운영 탭 전체.

**주소로 현재 위치 읽기**: 브라우저 주소도 같은 중첩 구조를 따름.
```
/{테넌트}/datasets/{데이터셋}/projects/{프로젝트}/versions/{스냅샷}/assets/{에셋}
```
- 앞에서 뒤로 갈수록 깊어짐(테넌트 → 데이터셋 → 프로젝트 → 스냅샷 → 에셋).
- 라이브 데이터는 `{스냅샷}` 자리에 `latest`, 특정 스냅샷은 해당 주소 사용.
- 프로젝트 설정은 `settings/members`, `settings/schema`처럼 뒤에 붙음.
- 모델·요청 현황·활동 기록은 데이터셋 바깥, 테넌트 바로 아래(`/{테넌트}/models`, `/{테넌트}/jobs` 등).

### 검색·명령 (⌘K)
어디서든 ⌘K(윈도우·리눅스는 Ctrl+K)로 여는 검색·명령 팔레트. 데이터셋·프로젝트·모델 등으로 바로 이동, 화면 이동/생성/테마 변경 같은 동작도 실행. 상단 바 "검색 / 명령" 칸 클릭으로도 오픈.

- **기본 제안**: 액션·이동 그룹으로 표시. 방향키 선택, Enter 실행, Esc 닫기. 자주 쓰는 항목은 최근 열람 순으로 상단에 노출. 관리자는 모델·멤버 등 권한 필요 항목도 함께 표시.
- **입력해서 좁히기**: 이름 일부 입력 시 데이터셋·프로젝트·스냅샷·모델·멤버가 실시간으로 좁혀짐. 한글 초성 검색(예: "ㄷㅅ") 지원, 띄어쓰기로 조건 추가(예: "데이터셋 rooftop"). 항목 클릭 시 해당 화면으로 즉시 이동.

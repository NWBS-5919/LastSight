# LastSight AI — 화면 구성 가이드

백엔드가 정의해둔 데이터 모델(`backend/app/models/schemas.py`)과 색상 시스템을 기준으로, 만들어야 할 화면 목록·레이아웃 뼈대·화면별로 표시할 데이터를 정리했다. 아래 내용은 픽셀 단위 시안이 아니라 **"이 영역엔 이 정보가 들어간다"**는 뼈대이니, 실제 비주얼 디자인은 자유롭게 만들면 된다.

> 이 문서는 원래 Claude Artifact로만 존재했다가, 2026-07-30 파이프라인 전면 개편(출구 통과 판정 폐기 → 관측 지속시간 모델, 관리구역 감시 기능 추가) 이후 그 내용에 맞춰 다시 정리해서 `docs/`에 파일로 옮긴 버전이다. 2026-07-31에 차별화 기능 3종(사고 리플레이·확인 우선순위·2차 확인)과 PPE 미착용 로그를 반영해 다시 갱신했다. 최신 기준은 `CLAUDE.md`와 `docs/development_log.md` 16~19, 38~40번 섹션.
>
> `frontend/`에 React+Vite 프로젝트가 이미 있다(작업 중). 이 문서는 "화면에 이 정보가 이렇게 들어가면 된다"는 뼈대이지 이미 구현된 걸 다시 설명하는 게 아니다 — 각 화면 옆 배지는 "백엔드 API가 이미 준비돼 있는지"를 뜻한다: `API 준비됨`이면 지금 바로 붙여서 개발할 수 있고, `API 확장 필요`면 백엔드 쪽 스키마·엔드포인트 작업이 먼저 필요하다(담당자와 상의). 전체 엔드포인트 목록·요청/응답 스키마는 백엔드 실행 후 `http://localhost:8000/docs`(Swagger)에서 항상 최신 상태로 확인 가능 — 이 문서와 다르면 Swagger 쪽을 신뢰할 것.

**기준 원칙**: 이 시스템은 어떤 경우에도 "대피 완료"·"전원 안전"을 AI 단독으로 확정 선언하지 않는다. 화재경보 이후에는 "지금도 관측되고 있는지 · 얼마나 오래 관측되고 있는지"만 보여주고, 관측이 끊긴 경우는 안전도 위험도 확정하지 않은 채 마지막 확인 시각·위치·신뢰도만 함께 보여준다(추정 정보임을 항상 드러낸다).

## 모드

- **평상시 모드**: 화재경보 없음. PPE 준수, 관리구역(소화기/전기패널/비상구) 상태를 상시 점검. 파란색 계열(`--color-inside-observed` 톤)로 화면 유지.
- **비상시 모드**: 화재경보 발생 후 자동 전환. 관측 지속 여부 추적·구조 브리핑 중심. 붉은색 계열(`--color-danger` 톤) 경보 톤으로 전환.

## 평상시 모드

### 1. 평상시 안전 대시보드 `API 준비됨`

화재경보가 없을 때 기본으로 보이는 화면. "지금 현장이 안전한 상태인가"를 한눈에 보여준다.

**레이아웃**
- 상단 요약 4칸: 오늘 PPE 미착용 건수 / 관리구역 이상 개소 / 구역별 현재 관측 인원 / 카메라 가동 상태
- 구역별 카드(Room 1/2/3 등): 구역명 + PPE 준수율
- **PPE 미착용 로그**(2026-07-31 신규): 시각 · 구역 · 어떤 장비(헬멧/조끼) 목록. 항목을 클릭하면 그 순간 증거 사진이 뜬다 — 아래 [공통 패턴](#공통-패턴--로그-클릭-시-증거-사진) 참고
- 최근 이벤트 피드: 시각 + 구역 + 내용, 최신순

**표시 데이터**

| 필드 | 타입 | 출처 |
|---|---|---|
| 오늘 미착용 적발 건수 | `int` | `GET /ppe/summary` → `violations_today` |
| 구역별 현재 관측 인원 | `int` | `GET /ppe/summary` → `zone_person_counts` |
| PPE 미착용 로그 목록 | `PpeViolationLogEntry[]` | `GET /ppe-violations/{camera_id}` — `track_id`/`violation`("helmet"\|"vest")/`zone`/`at`/`frame_path`/`bbox_xyxy`/`confidence` |
| 관리구역 이상 개소 | `int` | `GET /zone-maps/{camera_id}/clearance-zones/status`에서 `state === "abnormal"` 카운트, 2번 화면 연결 |
| 최근 이벤트 피드 | 시각+구역+내용 | `GET /ppe/summary` → `event_feed` |
| 카메라 가동 상태 | 가동/끊김 대수 | `GET /ppe/summary` → `camera_ok` |

> ⚠️ **추적 ID가 같은 사람을 계속 이어붙여주지 않는다.** CCTV 특성(작게 찍힘, 복장 통일)상 사람이 화면 밖으로 나갔다 다시 들어오면 새 `track_id`를 받는다 — 그래서 PPE 로그는 "ID별 위반 횟수"가 아니라 **"위반 건별 목록 + 사진"**으로 보여주고, 같은 사람인지는 관리자가 사진을 보고 직접 판단하게 한다(development_log.md 40번 참고). 목록에서 ID로 그룹핑하지 말 것.

**인터랙션**
- PPE 미착용 로그 항목 클릭 → 그 순간 프레임 사진 위에 박스 오버레이 표시
- 화재경보 발생 시 화면 전체가 3번(비상 대시보드)으로 자동 전환

### 2. 관리구역 점검 `API 준비됨`

소화기·전기패널·비상구 앞 공간이 기준 사진과 달라졌는지를 평면도 위에서 확인한다. 카메라 참조 이미지 위에 등록된 관리구역 폴리곤을 겹쳐 그리고, 그 위에 상태를 표시하는 오버레이 형태를 권장한다(구역 폴리곤과 관리구역 폴리곤을 같은 방식으로 그리되 색을 다르게 구분).

**레이아웃**
- 평면도(카메라 참조 이미지) 위에 등록된 관리구역을 폴리곤으로 표시 — 일반 구역과 구분되는 색(예: 보라색 점선)
- 각 폴리곤에 상태별 pill 표시: `normal`(정상) / `observing`(변화 감지, 지속시간 미달) / `abnormal`(15분 이상 지속 — 확인 필요) / `camera_failure`(카메라 확인 불가)
- 관리구역 목록: 구역명 · 종류(소화기/전기패널/비상구) · 상태 · 마지막 확인 시각

**표시 데이터**

| 필드 | 타입 | 비고 |
|---|---|---|
| 관리구역 ID·종류·폴리곤 | — | 관리자가 5번 화면에서 사전 등록 |
| 상태 | `ClearanceZoneState` | `normal`/`observing`/`abnormal`/`camera_failure` |
| 변화 감지 시작 시각 | `changed_since: ISO8601 \| null` | `observing`/`abnormal`일 때만 존재 |
| 마지막 확인 시각 | `last_checked_at: ISO8601` | |
| 확인 스냅샷 | `last_frame_path` | 참조 이미지 |

> 사람이 관리구역과 겹쳐 있는 동안은 판정을 하지 않고 직전 상태를 유지한다 — 지나가는 작업자를 방치물로 오인하지 않기 위함(CLAUDE.md 4-4 참고). 화면에도 "사람과 겹침 — 판정 보류" 같은 표시를 해주면 좋다.

## 비상시 모드

### 3. 비상 대시보드 `API 준비됨`

화재경보 발생 시 자동 전환되는 화면. 상단 요약 통계 + 평면도 마커 + 확인 우선순위 목록 조합.

**레이아웃**
- 상단 배너: 🔥 화재경보 — 발생 시각 · 발생 구역 · 트리거 방식(자동탐지/수동) · 신뢰도
- 요약 4칸: 관측 대상 인원 / 관측 중 / 장기 체류 경고 / 관측 안 됨 (`GET /workers/summary`)
- 평면도: 각 작업자의 마지막 관측 구역에 상태별 색상 마커(`inside_observed`=파랑, `prolonged_presence`=빨강, `tracking_lost`=회색, `camera_failure`=진회색)
- **확인 우선순위 목록**(2026-07-31 신규): 장기 체류 경고/관측 안 됨 인원을 점수 내림차순으로. `GET /workers/priority/ranked` — 각 항목에 `total_score`와 구성요소(`duration_minutes`/`duration_score`/`distance_px`/`proximity_score`/`confidence_score`)가 그대로 담겨 있으니, "왜 이 순서인지" 펼쳐보는 UI(예: 클릭하면 점수 breakdown 표시)를 권장한다. **위험도 확정이 아니라 참고 순위라는 걸 문구로 드러낼 것** (예: "확인 권장 순서" 정도의 톤, "위험 순위"라는 표현 금지)

**표시 데이터 (장기 체류 경고 / 관측 안 됨 작업자 카드)** — 전부 `GET /workers` (`WorkerStatus[]`)에 이미 있는 필드

| 필드 | 타입 | 비고 |
|---|---|---|
| 마지막 확인 시각 | `last_seen_at: ISO8601` | |
| 마지막 확인 위치 | `last_zone` | |
| 탐지 신뢰도 | `confidence: 0~1` | |
| 시야 확보 여부 | `visibility: "높음"\|"중간"\|"낮음"` | |
| **2차 확인 결과** | `situation_note: string \| null` | 2026-07-31 신규. `prolonged_presence` 전환 직후 비동기로 채워지므로, 카드 뜨자마자는 비어있다가 몇 초 뒤 채워질 수 있다 — 로딩 상태(예: "확인 중…")를 자연스럽게 표시할 것 |
| **확인 우선순위 점수** | `priority_score: 0~100 \| null` | `GET /workers/priority/ranked`에서 채워짐, `GET /workers`에는 항상 `null` |
| 참조 이미지 | `reference_frame_path` | 가장 선명한 프레임 |
| 헬멧·조끼 색상 | `helmet_color`/`vest_color` | 인상착의 보조 정보 |

> "잔류 인원 N명"처럼 단정하는 문구 금지. `tracking_lost`는 안전도 위험도 아니다 — "관측 안 됨(마지막 확인: OO시 OO분, B구역)"처럼 사실만 표시한다. `prolonged_presence`도 "구조 필요 확정"이 아니라 "확인 필요" 신호로만 표시한다.

### 4. 구조 브리핑 카드 `API 준비됨`

출동한 소방대원이 즉시 훑어볼 수 있는 인쇄/모바일용 요약 카드. `GET /briefing/{track_id}`로 조회.

**레이아웃**
- 참조사진 + 추적 ID + 마지막 관측 구역·시각 + 헬멧/조끼 색상
- 상태 뱃지(`inside_observed`/`prolonged_presence`/`tracking_lost`/`camera_failure`) + 신뢰도 + 시야 확보 여부
- 2차 확인 결과(`situation_note`)가 있으면 카드에 짧게 노출

**인터랙션 · 문구 원칙**
- 카드 상단에 "추정 정보 — 확정 아님" 라벨 상시 노출
- 다국어 대피 문구는 이 화면이 아니라 대피 유도용 별도 사이니지 문구 — 필요 시 문의
- 인쇄 버튼 / 소방대 공유용 링크 복사 버튼

### 5. 구역·관리구역 설정 `API 준비됨`

관리자가 카메라 화면 위에 클릭으로 구역·관리구역 폴리곤을 그리는 설정 화면. 관련 CRUD API(`backend/app/api/zone_maps.py`)는 이미 다 되어 있어서 바로 화면만 붙이면 된다.

**레이아웃**
- 카메라 참조 이미지 위 클릭으로 폴리곤 점을 찍고 완료 버튼으로 확정
- "구역 그리기" / "관리구역 그리기"(종류 선택: 소화기/전기패널/비상구) 버튼
- 관리구역은 등록 후 별도로 "기준 화면"을 업로드해야 감시가 시작된다 (`POST /zone-maps/{camera_id}/clearance-zones/{zone_id}/baseline`)

**준비된 API**
- 구역·관리구역 폴리곤 CRUD(`GET`/`PUT /zone-maps/{camera_id}`)
- 관리구역 기준 사진 등록·상태 조회·프레임 평가·조치완료(`/zone-maps/{camera_id}/clearance-zones/{zone_id}/...`)
- 전체 엔드포인트 목록·요청/응답 스키마는 백엔드 실행 후 `http://localhost:8000/docs`에서 확인

### 6. 사고 리플레이 `API 준비됨`

화재경보/작업자 상태변화/관리구역 상태변화/PPE 미착용을 한 타임라인으로 병합해서, 사고 이후 감사·훈련용으로 다시 훑어보는 화면(2026-07-31 신규). 비상 대시보드에서 화재경보가 끝난 뒤 진입하는 별도 탭/모달로 만들면 된다.

**레이아웃**
- 시간순 이벤트 목록(스크롤형) — `GET /incidents/{camera_id}/timeline`. 각 줄에 소스별 아이콘(🔥 화재경보 / 👤 작업자 / 🚧 관리구역 / 🦺 PPE) + 시각 + 한 줄 설명(`text`), `frame_path`가 있으면 클릭해서 사진 보기
- (선택, 시간 되면) **타임 슬라이더**: 특정 시각을 드래그해서 고르면 `GET /incidents/{camera_id}/state-at?at=...`로 그 순간의 전체 상태(화재경보 여부, 작업자별 상태, 관리구역별 상태)를 한 번에 재구성해서 평면도에 그대로 반영

**표시 데이터**

| 필드 | 타입 | 비고 |
|---|---|---|
| 타임라인 목록 | `IncidentTimelineEntry[]` | `at`/`source`/`text`/`track_id`/`zone_id`/`situation_note`/`frame_path`/`bbox_xyxy` |
| 특정 시각 스냅샷 | `{fire_alert, workers, clearance_zones}` | `state-at` 응답 — 각 작업자/구역의 그 시각 당시 마지막 로그 항목 |

> `source`가 `"worker"`/`"ppe_violation"`인 항목은 `frame_path`+`bbox_xyxy`가 있을 수 있다 — 아래 공통 패턴 참고.

## 공통 패턴 — 로그 클릭 시 증거 사진

PPE 미착용 로그, 작업자 상태변화 로그, 사고 리플레이 타임라인 모두 같은 모양의 필드(`frame_path` + `bbox_xyxy`)를 갖고 있다. 로그 한 줄을 클릭하면:

1. `frame_path`를 이미지로 띄운다(이미 있는 `frameUrl()` 헬퍼로 절대 URL 변환)
2. 그 위에 `bbox_xyxy` 박스 하나를 그린다 — **`DetectionOverlay.tsx`를 그대로 재사용 가능**하다. 지금은 `detections: Detection[]`(여러 개) 형태를 받는데, 단일 로그 항목은 `[{ object_class: entry.violation ?? "확인 필요", confidence: entry.confidence ?? 1, bbox_xyxy: entry.bbox_xyxy }]`처럼 배열 하나짜리로 감싸서 그대로 넘기면 된다.

**같은 사람인지 AI가 판단해주지 않는다.** 추적 ID가 바뀌어도 로그는 그냥 새 건으로 계속 쌓이도록 설계했다(위 1번 화면의 경고 박스 참고). 화면에서도 로그를 ID로 묶거나 "동일인 추정" 같은 걸 자동으로 표시하지 말 것 — 관리자가 사진을 보고 직접 판단하는 게 이 설계의 핵심이다.

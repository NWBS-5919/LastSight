# LastSight AI — 화면 구성 가이드

백엔드가 정의해둔 데이터 모델(`backend/app/models/schemas.py`)과 실제 구현된 프론트엔드(`frontend/src/App.tsx` 이하)를 기준으로, 지금 화면이 어떻게 구성돼 있는지 정리했다. 원래 이 문서는 "만들어야 할 화면 목록"이었지만, 실제 개발 과정에서 사용자와 직접 화면을 보면서 계속 고쳐나간 결과 처음 구상과는 상당히 달라졌다 — **이제는 사후 문서(무엇을 만들었는지 설명)이지 사전 스펙(무엇을 만들지 지시)이 아니다.** 코드와 이 문서가 다르면 코드를 신뢰할 것.

> 이 문서는 2026-08-04 기준으로 전면 재작성됐다(그 전 버전은 6개 화면·개인별 추적 상태 기반 설계였는데, 실제로는 개인별 추적을 걷어내고 화면도 하나로 합쳐졌다 — `CLAUDE.md`의 2026-08-04 메모, `docs/development_log.md` 51·53·54·56번 참고). 이전 버전이 궁금하면 git 이력에서 확인할 것.

**기준 원칙**: 이 시스템은 어떤 경우에도 "대피 완료"·"전원 안전"을 AI 단독으로 확정 선언하지 않는다. 화재경보 이후에는 매초 그 프레임을 다시 확인해 "지금 이 순간 무엇이 보이는지"만 카드로 남기고, 우려 신호(쓰러진 사람/연기에 둘러싸인 사람)가 잡혀도 "확인이 필요하다"는 신호일 뿐 확정이 아니다(추정 정보임을 항상 드러낸다).

**한 문장 요약(비개발자용)**: 공사현장 CCTV를 평소엔 "안전모/조끼를 안 쓴 사람"을 계속 감시하다가, 불이 나면 화면이 자동으로 비상 모드로 바뀌면서 "지금 몇 명이 카메라에 보이고, 그중 쓰러졌거나 연기에 둘러싸인 사람이 있는지"를 매초 확인해 카드로 쌓아준다. 위/아래 두 상태를 한 타임라인으로 이어서 보여주고, 영상 옆 채팅창에 자유롭게 물어보면 지금까지 상황을 근거로 답해준다("74초쯤 무슨 일이 있었어?" 같은 특정 시점 질문도 그때 저장된 사진을 찾아 답함). **사람 이름이나 얼굴은 절대 안 쓰고, "대피 완료" 같은 확정 문구도 절대 쓰지 않는다.**

## 화면은 하나다

원래 6개 화면(평상시 대시보드/비상 대시보드/구조 브리핑 카드/구역 설정/사고 리플레이)으로 나눠서 구상했지만, 실제로는 **`App.tsx` 페이지 하나**가 화재경보 유무에 따라 테마·통계 카드만 자동으로 바뀌고(파랑/평상시 ↔ 빨강/비상시), 세부 정보는 모달로 여닫는 구조로 정착했다. 별도 라우팅이 없다.

| 항목 | 구현 | [왜 이렇게 됐는지] |
|---|---|---|
| 모드 자동 전환 | 웹소켓으로 받는 `fire_alert`가 `null`이 아니면 헤더 배지가 `SYS-NORMAL`→`SYS-ALERT`, 상단에 화재경보 배너 표시, 통계 카드 구성이 바뀜 | 사람이 버튼을 눌러서 바꾸는 게 아님 — 급할 때 관리자가 못 누를 수 있으므로 |
| 실시간 갱신 | 웹소켓(`app/ws/live.py`)으로 매 프레임 스냅샷 전체를 그대로 받아 화면을 갈아끼움(`useLiveState` 훅) | 폴링·F5 없이 항상 최신 상태 |
| 영상 재생 | `<video>` 태그로 원본 영상을 그대로 재생하고, 그 위에 SVG로 박스만 주기적으로 갱신(`DetectionOverlay.tsx`) — 정지 이미지 슬라이드쇼가 아니라 매끄러운 영상 | 영상은 Render 서버를 거치지 않고 브라우저가 GitHub Release URL로 직접 요청(`docs/development_log.md` 58번) |
| 영상 옆 채팅 패널 | 시나리오가 시작되면(`scenario_started_at`이 생기면) 영상 오른쪽에 `SituationChatPanel.tsx`가 나타남(`.camera-row` flex 배치) | 예전엔 오른쪽 사이드바(EventFeed)가 타임라인 너비를 잡아먹어 없앤 적이 있어, 이번엔 영상 높이만큼만 차지하고 아래 타임라인은 그대로 전체 너비를 씀 |

## 상단 헤더 + 통계 카드

- 로고/타이틀 + 모드 배지, "구역 보기"·"시나리오 시작"·"초기화" 버튼
- 통계 카드(평상시): 오늘 PPE 미착용 적발 건수, 현재 관측 인원, **구역별 카드**(zone-maps API로 받아온 전체 구역 목록을 항상 표시 — 그 순간 아무도 없어도 "0명"으로 보여줌)
- 통계 카드(비상시): 현재 관측 인원, 구역별 카드. 예전엔 "이상상황 감지" 건수도 있었으나 "1초마다 찍는 확인 스냅샷 개수"일 뿐 실제 위험도가 아니라는 문제로 제거함(아래 구조 카드로 이미 확인 가능해 중복 판단)

## 통합 타임라인 (`DashboardTimeline.tsx`)

가장 중심이 되는 컴포넌트. 시나리오 시작 시각(t=0)을 기준으로, 평상시 PPE 위반 이력 → 화재 발생 → 화재 이후 2차 확인 이정표를 **한 줄에 이어서** 그린다(예전엔 평상시/비상시 타임라인이 따로 있어서 화재가 나면 이전 기록이 화면에서 사라지는 문제가 있었음).

| 요소 | 동작 | 비고 |
|---|---|---|
| PPE 위반 노드 | 위반이 새로 감지될 때마다 노드 하나. 클릭하면 `PpeViolationEditModal` — 그 순간 bbox·프레임 확인 + 안전모/안전조끼 각각 착용·미착용으로 정정 | 정정해도 AI 원판정은 감사 기록으로 남음(`reviewed_*` 필드가 별도) |
| 화재 발생 노드 | 원형 dot 대신 발광 효과가 있는 불꽃 아이콘. 클릭하면 `FireAlertModal`(발생 일시·트리거 방식·신뢰도·구역). 라벨 아래에 상대 시각(+61초)뿐 아니라 절대 시각도 표시 | |
| 2차 확인 이정표 | 카테고리별 "지금까지의 최고 인원 기록"을 새로 경신할 때만 이정표로 뽑음(매초 쌓이는 카드를 다 표시하면 화면이 도배되므로). 클릭하면 `SituationDetailModal` | 마지막엔 "종료 시점 · 체류중 N명" 고정 이정표 |
| 라벨 배치 | 여러 이정표가 시간상 가까우면 위/아래 여러 단(tier)에 자동으로 나눠 배치(`timelineLayout.ts`), 각 dot에서 라벨까지 연결선(로그팝 스타일)으로 이어줌 | |
| 드래그로 병합 | 위치 매칭 실패로 같은 사람의 같은 위반이 노드 두 개로 쪼개진 경우, PPE 노드끼리 서로 끌어다 놓으면 하나로 합쳐짐(`POST /ppe-violations/{camera_id}/merge`) — 더 이른 시점의 프레임·데이터가 남음 | 화재/2차확인 노드는 드래그 대상 아님 |

## 구조 브리핑 챗봇 (`SituationChatPanel.tsx`)

2026-08-05: 한 번 누르면 headline+points를 한 번만 반환하던 "요약 브리핑" 버튼을 대화형 채팅 패널로 바꿨다. 시나리오가 시작되면 영상 옆에 나타나며, 처음엔 빈 채로 시작해 관리자가 입력창에 질문을 넣어야 답이 온다(초기에는 패널이 뜨자마자 요약 질문을 자동 전송했는데, 시나리오를 시작할 때마다 원치 않는 호출이 발생한다는 피드백으로 없앴다).

| 기능 | 동작 | 비고 |
|---|---|---|
| 데이터 기반 답변 | 매 턴 최신 화재경보·구역인원·2차 확인·PPE 위반 데이터를 다시 정리해서 Gemini에게 넘김(`app/inference/briefing.py`의 `answer_chat_message`, `POST /situation-chat`) | 대화가 길어지는 동안 상황이 바뀌어도(예: 화재 발생) 다음 답변에 바로 반영됨 |
| 시간 힌트 인식 | "74초쯤", "화재 나고 12초 후", "오후 9시 55분쯤" 같은 표현을 정규식으로 인식해 그 시점에 저장된 프레임을 찾아 답변에 곁들임(`parse_time_hint`/`find_frame_near`) | 화재 전후 상관없이 `data/demo/scenario.json`의 사전계산 프레임까지 포함해 항상 어떤 사진이든 찾아줌 |
| 참고 사진 표시 | 답변에 참고 프레임이 있으면 말풍선 안에 작은 썸네일로 표시, 클릭하면 확대(라이트박스) | |
| 안전 원칙 | "그래서 다 안전한 거 맞지?" 같은 유도신문에도 확정 선언 거부, PPE는 "명"이 아니라 "건"으로 답변, 사진 없는 구간은 모른다고 답함 | 시스템 프롬프트에 명시적으로 강제 |
| 마크다운 후처리 | Gemini가 "마크다운 쓰지 마라" 지시를 완벽히 안 지켜서(`**`/`#`/`---`/번호 목록이 섞여 나옴) 응답을 받은 뒤 정규식으로 한 번 더 걷어냄(`_strip_markdown`) | 프롬프트만 믿지 않는 안전망 |

## 카드 그리드 (기본 접힘)

타임라인 아래에 "안전장비 위반 카드"·"구조 카드" 두 섹션이 토글 버튼으로 접혀 있다(기본 숨김 — 클릭해서 펼침).

| 섹션 | 카드 | 표시 데이터 |
|---|---|---|
| 안전장비 위반 카드 | `PpeViolationCard.tsx` | 시각·구역·안전모/안전조끼 유효 상태(정정됐으면 정정값), 클릭하면 정정 모달 |
| 구조 카드 | `SituationCard.tsx` | "화재 발생 후 N초", 총 감지 인원, 카테고리별 인원(체류중/쓰러진 사람/연기에 둘러싸인 사람), 우려 신호 있으면 "확인 필요" 배지 |

두 카드 디자인은 동일한 시각 언어(좌측 색 테두리 + 배지 + disclaimer)를 쓴다.

## 구역 보기 / 구역 편집 (`ZoneMapModal.tsx`)

헤더의 "구역 보기" 버튼으로 연다. 카메라 첫 프레임(`0000.jpg`) 위에 등록된 구역 폴리곤을 색으로 칠해 보여준다("A구역"이라는 이름만으론 실제 화면 어디인지 알기 어려운 문제 해결).

- **보기 모드**(기본): 구역 폴리곤 + 이름만 표시
- **편집 모드**("편집" 버튼): 화면 클릭으로 새 폴리곤을 그리고 이름을 입력해 구역 추가, 기존 구역 삭제, "저장"으로 `PUT /zone-maps/{camera_id}` 호출
- 백엔드(`app/rules/zone.py`)는 이미 임의 개수·모양의 폴리곤을 그대로 처리하므로, 몇 개를 어떤 이름으로 그리든 대시보드 통계 카드·PPE/2차확인 로그의 구역 라벨에 그대로 반영된다

> 구역을 저장해도 시나리오를 다시 시작할 때 초기값으로 되돌아가지 않는다(`_register_demo_zone_map()`은 구역 설정 파일이 아예 없는 최초 부팅 시에만 기본값을 만듦 — `docs/development_log.md` 54번 참고).

## 공통 패턴 — 로그 클릭 시 증거 사진

PPE 위반 카드, 구조 카드 모두 클릭하면 그 순간 프레임 사진 위에 bbox를 그려서 보여준다(`DetectionOverlay.tsx`의 SVG 오버레이 방식을 재사용). **같은 사람인지 AI가 판단해주지 않는다** — 복장·위치만으로 동일인 병합을 자동으로 하지 않고, 관리자가 사진을 보고 직접 판단하는 게 설계 원칙이다.

## 백엔드는 준비됐지만 화면이 아직 없는 것

아래는 API·규칙 엔진은 구현돼 있고 테스트도 통과하지만, 시간 관계상 프론트엔드 화면을 아직 안 붙인 기능이다. Swagger(`http://localhost:8000/docs`)에서 바로 확인 가능하고, 화면만 붙이면 동작한다.

| 기능 | 준비된 API | 비고 |
|---|---|---|
| 사고 리플레이 | `app/api/incidents.py` — 화재경보/PPE 로그를 병합한 시간순 타임라인 + 특정 시각 상태 재구성 | |
| 개인별 구조 브리핑 카드(`app/api/briefing.py`) | `GET /briefing/{track_id}` | 2026-08-04 개인별 추적을 걷어내며 사실상 안 씀(`_current_workers()`가 항상 빈 리스트) — 지우지 않고 vestigial로 남겨둠 |

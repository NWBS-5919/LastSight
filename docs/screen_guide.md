# LastSight AI — 화면 구성 가이드

백엔드가 정의해둔 데이터 모델(`backend/app/models/schemas.py`)과 색상 시스템을 기준으로, 만들어야 할 화면 목록·레이아웃 뼈대·화면별로 표시할 데이터를 정리했다. 아래 내용은 픽셀 단위 시안이 아니라 **"이 영역엔 이 정보가 들어간다"**는 뼈대이니, 실제 비주얼 디자인은 자유롭게 만들면 된다.

> 이 문서는 원래 Claude Artifact로만 존재했다가, 2026-07-30 파이프라인 전면 개편(출구 통과 판정 폐기 → 관측 지속시간 모델, 관리구역 감시 기능 추가) 이후 그 내용에 맞춰 다시 정리해서 `docs/`에 파일로 옮긴 버전이다. 2026-07-31에 차별화 기능 3종(사고 리플레이·확인 우선순위·2차 확인)과 PPE 미착용 로그를 반영해 갱신했고, 2026-08-02에 평상시/비상시 파이프라인 재설계(평상시 추적 제거, 화재경보 후에만 추적 시작, 헬멧/조끼 개별 토글, 구역별 상황 집계 로그, 실시간 관측중/장기체류 박스 색상)와 그 뒤 보완(평상시 실시간 착용 라벨 데이터, 구역 집계 로그의 사람별 박스 저장)을 반영해 다시 갱신했다. 최신 기준은 `CLAUDE.md`와 `docs/development_log.md` 16~19, 38~40, 46~47번 섹션.
>
> `frontend/`에 React+Vite 프로젝트가 이미 있다(작업 중). 이 문서는 "화면에 이 정보가 이렇게 들어가면 된다"는 뼈대이지 이미 구현된 걸 다시 설명하는 게 아니다 — 각 화면 옆 배지는 "백엔드 API가 이미 준비돼 있는지"를 뜻한다: `API 준비됨`이면 지금 바로 붙여서 개발할 수 있고, `API 확장 필요`면 백엔드 쪽 스키마·엔드포인트 작업이 먼저 필요하다(담당자와 상의). 전체 엔드포인트 목록·요청/응답 스키마는 백엔드 실행 후 `http://localhost:8000/docs`(Swagger)에서 항상 최신 상태로 확인 가능 — 이 문서와 다르면 Swagger 쪽을 신뢰할 것.

**기준 원칙**: 이 시스템은 어떤 경우에도 "대피 완료"·"전원 안전"을 AI 단독으로 확정 선언하지 않는다. 화재경보 이후에는 "지금도 관측되고 있는지 · 얼마나 오래 관측되고 있는지"만 보여주고, 관측이 끊긴 경우는 안전도 위험도 확정하지 않은 채 마지막 확인 시각·위치·신뢰도만 함께 보여준다(추정 정보임을 항상 드러낸다).

**한 문장 요약(비개발자용)**: 공사현장 CCTV를 평소엔 "안전모/조끼를 안 쓴 사람, 소화기 앞이 막혔는지"를 계속 감시하다가, 불이 나면 화면이 자동으로 비상 모드로 바뀌면서 "누가 지금도 카메라에 보이는지, 얼마나 오래 보이고 있는지"를 정리해서 보여주는 대시보드다. **사람 이름이나 얼굴은 절대 안 쓰고 `T0001` 같은 임시 번호로만 부르며, "대피 완료" 같은 확정 문구도 절대 쓰지 않는다** — 이 두 가지는 화면 문구를 쓸 때 가장 자주 어기기 쉬운 규칙이니 항상 주의할 것.

## 평상시 모드

### 1. 평상시 안전 대시보드 `API 준비됨`

화재경보가 없을 때 기본으로 보이는 화면. "지금 현장이 안전한 상태인가"를 한눈에 보여준다.

**레이아웃**
- 상단 요약 4칸: 오늘 PPE 미착용 건수 / 관리구역 이상 개소 / 구역별 현재 관측 인원 / 카메라 가동 상태
- **실시간 카메라 화면**(2026-08-02 신규): 사람마다 bbox를 그리고, 그 위에 "헬멧 착용"/"헬멧 미착용"·"조끼 착용"/"조끼 미착용" 라벨을 얹는다. 추적을 안 쓰므로 ID는 없고 매 프레임 다시 계산된 스냅샷이다(§주의 참고).
- 구역별 카드(Room 1/2/3 등): 구역명 + PPE 준수율
- **헬멧/조끼 감지 on/off 토글**(2026-08-02 신규): 카메라별로 헬멧·조끼 감지를 각각 켜고 끌 수 있는 스위치 2개(예: "이 현장은 조끼 규정 없음" 같은 경우 조끼 감지만 끔). `GET`/`PUT /ppe-settings/{camera_id}`
- **PPE 미착용 로그**: 시각 · 구역 · 어떤 장비(헬멧/조끼, 둘 다면 "헬멧, 조끼" 한 줄) 목록. 항목을 클릭하면 그 순간 증거 사진이 뜬다 — 아래 [공통 패턴](#공통-패턴--로그-클릭-시-증거-사진) 참고
- 최근 이벤트 피드: 시각 + 구역 + 내용, 최신순

**표시 데이터**

| 필드 | 타입 | 출처 |
|---|---|---|
| 실시간 사람별 착용 라벨 | `PersonComplianceBox[]` | `GET /scenario/state`(또는 웹소켓) → `current_person_compliance` — `bbox_xyxy`/`zone`/`helmet`("worn"\|"not_worn"\|"unknown")/`vest`/`confidence`. 화면에 "헬멧 (미)착용"·"조끼 (미)착용" 라벨은 이 값으로 그린다. `unknown`은 판단 근거 자체가 안 잡힌 경우이니 "미착용"으로 단정하지 말고 "확인 불가" 톤으로 구분 표시할 것 |
| 실시간 원본 탐지 박스 | `Detection[]` | `GET /scenario/state` → `current_detections` — person/helmet/vest 원본 박스(사람별로 묶이지 않은 raw 박스, 디버그/보조용) |
| 오늘 미착용 적발 건수 | `int` | `GET /ppe/summary` → `violations_today` |
| 구역별 현재 관측 인원 | `int` | `GET /ppe/summary` → `zone_person_counts` |
| PPE 미착용 로그 목록 | `PpeViolationLogEntry[]` | `GET /ppe-violations/{camera_id}` — `violations`(`["helmet"]`\|`["vest"]`\|`["helmet","vest"]`)/`zone`/`at`/`frame_path`/`bbox_xyxy`/`confidence`. `track_id` 필드 자체가 없다(아래 경고 참고) |
| 헬멧/조끼 감지 설정 | `PpeDetectionSettings` | `GET /ppe-settings/{camera_id}` — `detect_helmet`/`detect_vest` (기본 둘 다 `true`) |
| 관리구역 이상 개소 | `int` | `GET /zone-maps/{camera_id}/clearance-zones/status`에서 `state === "abnormal"` 카운트, 2번 화면 연결 |
| 최근 이벤트 피드 | 시각+구역+내용 | `GET /ppe/summary` → `event_feed` |
| 카메라 가동 상태 | 가동/끊김 대수 | `GET /ppe/summary` → `camera_ok` |

> `current_person_compliance`는 **누적 로그가 아니라 이번 프레임 스냅샷**이다 — 매번 통째로 갈아끼우면 되고, 이전 프레임 값과 비교해서 "새로 미착용이 됐다" 같은 걸 프론트가 직접 판단하지 말 것(그 판단과 기록은 이미 백엔드의 PPE 미착용 로그가 담당한다). 헬멧/조끼 감지가 꺼져 있으면(`PpeDetectionSettings`) 그 항목은 항상 `unknown`으로 온다.

> ⚠️ **평상시엔 추적(track_id) 자체를 쓰지 않는다.** 사람이 화면을 들락날락할 때마다 ID가 계속 새로 매겨져서 의미가 없기 때문에(development_log.md 43번), 평상시 person/helmet/vest 감지는 매 프레임 독립적으로 판정하고 추적을 아예 안 한다. 그래서 `PpeViolationLogEntry`엔 `track_id`가 없다 — 위반은 "같은 구역·비슷한 위치에서 최근 30초 이내 같은 조합으로 계속되는 위반인지"만 보고 중복 없이 기록한다(위치+시간 기반 dedup, `app/rules/ppe_violation_log.py`). 화면에서도 로그를 사람 ID로 그룹핑하지 말 것 — 같은 사람인지는 사진을 보고 관리자가 직접 판단.

**버튼/인터랙션**

| 버튼·요소 | 누르면 일어나는 일 | [왜 필요한지] |
|---|---|---|
| 구역 카드(Room 1/2/3 등) 클릭 | 그 구역의 최근 위반 스냅샷 목록으로 스크롤/필터 | "이 구역이 왜 준수율이 낮지?"를 바로 파고들 수 있게 |
| PPE 미착용 로그 항목 클릭 | 그 순간 프레임 사진 위에 박스 오버레이 표시 (§공통 패턴 참고) | 글자로만 된 로그는 못 믿는 관리자도 있으니, 실제 장면을 보여줘야 설득력이 있음 |
| 헬멧/조끼 감지 토글 스위치 | `PUT /ppe-settings/{camera_id}`로 즉시 저장, 다음 프레임부터 반영 | 현장 규정에 안 맞는 항목까지 오탐/과다 경고가 뜨는 걸 막기 위함 |
| (화재경보 발생 시) | 관리자가 아무것도 안 눌러도 화면 전체가 §3 비상 대시보드로 자동 전환 | 위 "모드 자동 전환" 원칙과 동일 |

### 2. 관리구역 점검 `API 준비됨`

소화기·전기패널·비상구 앞 공간이 기준 사진과 달라졌는지를 평면도 위에서 확인한다. 카메라 참조 이미지 위에 등록된 관리구역 폴리곤을 겹쳐 그리고, 그 위에 상태를 표시하는 오버레이 형태를 권장한다(구역 폴리곤과 관리구역 폴리곤을 같은 방식으로 그리되 색을 다르게 구분).

**레이아웃**
- 평면도(카메라 참조 이미지) 위에 등록된 관리구역을 폴리곤으로 표시 — 일반 구역과 구분되는 색(예: 보라색 점선)
- 각 폴리곤에 상태별 pill 표시: `normal`(정상) / `observing`(변화 감지, 지속시간 미달) / `abnormal`(15분 이상 지속 — 확인 필요) / `camera_failure`(카메라 확인 불가)
- 관리구역 목록: 구역명 · 종류(소화기/전기패널/비상구) · 상태 · 마지막 확인 시각

**표시 데이터**

| 필드 | 타입 | 비고 |
|---|---|---|
| 관리구역 ID·종류·폴리곤 | — | 관리자가 5번 화면에서 사전 등록 |
| 상태 | `ClearanceZoneState` | `normal`/`observing`/`abnormal`/`camera_failure` |
| 변화 감지 시작 시각 | `changed_since: ISO8601 \| null` | `observing`/`abnormal`일 때만 존재 |
| 마지막 확인 시각 | `last_checked_at: ISO8601` | |
| 확인 스냅샷 | `last_frame_path` | 참조 이미지 |

> 사람이 관리구역과 겹쳐 있는 동안은 판정을 하지 않고 직전 상태를 유지한다 — 지나가는 작업자를 방치물로 오인하지 않기 위함(CLAUDE.md 4-4 참고). 화면에도 "사람과 겹침 — 판정 보류" 같은 표시를 해주면 좋다.

**버튼/인터랙션**

| 버튼·요소 | 누르면 일어나는 일 | [왜 필요한지] |
|---|---|---|
| 평면도 위 관리구역 폴리곤 클릭 | 그 구역의 상세 패널(종류·상태·마지막 확인 시각·기준 사진 vs 현재 사진 비교) 팝업 | "정확히 뭐가 달라졌는지" 사진 두 장을 나란히 봐야 관리자가 판단 가능 |
| 목록에서 행 클릭 | 위와 동일하게 상세 패널 열기(평면도 대신 표로 접근하는 경로) | 관리구역이 많을 때 평면도보다 표가 스캔하기 빠름 |
| "조치 완료" 버튼(상세 패널 안) | `POST .../resolve` 호출 — 상태를 `normal`로 되돌림(새 기준 사진 첨부 가능) | 관리자가 현장 가서 물건 치운 뒤, 시스템에 "다시 정상"이라고 알려주는 유일한 방법(자동 복구 안 됨) |

- 요약 4칸: 관측 대상 인원 / 관측 중 / 장기 체류 경고 / 관측 안 됨 (`GET /workers/summary`)
- 평면도: 각 작업자의 마지막 관측 구역에 상태별 색상 마커(`inside_observed`=파랑, `prolonged_presence`=빨강, `tracking_lost`=회색, `camera_failure`=진회색)
- **실시간 영상 오버레이**(2026-08-02 신규): 화재경보가 뜬 순간부터 추적이 시작되므로, 카메라 화면 위에 사람마다 박스를 그릴 수 있다. `WorkerStatus.current_bbox_xyxy`가 채워져 있으면(이번 프레임에 실제로 보이는 사람만) `event`에 따라 **관측중=초록 박스 / 장기체류=빨강 박스**로 그린다. 값이 `null`이면(관측 안 됨) 박스를 그리지 않는다 — 평상시엔 이 필드가 항상 비어 있다(추적을 안 하므로).
- **구역별 상황 집계 로그**(2026-08-02 신규): 장기체류 전환이 하나라도 생길 때마다 전체 구역을 다시 집계해 "A구역 총 4명(체류중 1, 쓰러진 사람 3)" 같은 한 줄로 남긴다. `GET /zone-situation/{camera_id}` — 항목마다 `zones[].total`/`breakdown`(카테고리별 인원수)과 `frame_path`(클릭하면 그 순간 전체 장면 사진). **캡처 사진은 카메라 화면 전체를 찍은 한 장이고, 구역별로 따로 찍지 않는다** — 사진 한 장 안에 여러 구역 사람이 같이 찍혀 있을 수 있다. 이 사진 위에 "어느 사람이 쓰러진 사람인지" 박스로 표시하려면 `zones[].boxes`(사람별 `category`+`bbox_xyxy`, `len(boxes) === total`)를 그대로 그리면 된다 — 카테고리별로 다른 색(예: 쓰러진 사람=빨강, 연기에 갇힘=주황, 체류중=회색)을 권장. 이 로그도 §6 사고 리플레이 타임라인에 `zone_situation` 소스로 같이 병합된다(단, 타임라인의 한 줄 요약 텍스트에는 `boxes`가 포함되지 않으니 박스까지 그리려면 이 API를 직접 호출할 것).
- **확인 우선순위 목록**: 장기 체류 경고/관측 안 됨 인원을 점수 내림차순으로. `GET /workers/priority/ranked` — 각 항목에 `total_score`와 구성요소(`duration_minutes`/`duration_score`/`distance_px`/`proximity_score`/`confidence_score`)가 그대로 담겨 있으니, "왜 이 순서인지" 펼쳐보는 UI(예: 클릭하면 점수 breakdown 표시)를 권장한다. **위험도 확정이 아니라 참고 순위라는 걸 문구로 드러낼 것** (예: "확인 권장 순서" 정도의 톤, "위험 순위"라는 표현 금지)

**표시 데이터 (장기 체류 경고 / 관측 안 됨 작업자 카드)** — 전부 `GET /workers` (`WorkerStatus[]`)에 이미 있는 필드

### 5. 구역·관리구역 설정 `API 준비됨`

### 6. 사고 리플레이 `API 준비됨`

화재경보/작업자 상태변화/관리구역 상태변화/PPE 미착용을 한 타임라인으로 병합해서, 사고 이후 감사·훈련용으로 다시 훑어보는 화면(2026-07-31 신규). 비상 대시보드에서 화재경보가 끝난 뒤 진입하는 별도 탭/모달로 만들면 된다.

**레이아웃**
- 시간순 이벤트 목록(스크롤형) — `GET /incidents/{camera_id}/timeline`. 각 줄에 소스별 아이콘(🔥 화재경보 / 👤 작업자 / 🚧 관리구역 / 🦺 PPE / 🧭 구역집계) + 시각 + 한 줄 설명(`text`), `frame_path`가 있으면 클릭해서 사진 보기
- (선택, 시간 되면) **타임 슬라이더**: 특정 시각을 드래그해서 고르면 `GET /incidents/{camera_id}/state-at?at=...`로 그 순간의 전체 상태(화재경보 여부, 작업자별 상태, 관리구역별 상태)를 한 번에 재구성해서 평면도에 그대로 반영

**표시 데이터**

| 필드 | 타입 | 비고 |
|---|---|---|
| 타임라인 목록 | `IncidentTimelineEntry[]` | `at`/`source`("fire_alert"\|"worker"\|"clearance_zone"\|"ppe_violation"\|"zone_situation")/`text`/`track_id`/`zone_id`/`situation_note`/`frame_path`/`bbox_xyxy`. `track_id`는 `source==="worker"`일 때만 채워짐(그 외 소스는 특정 사람 ID를 안 씀) |
| 특정 시각 스냅샷 | `{fire_alert, workers, clearance_zones}` | `state-at` 응답 — 각 작업자/구역의 그 시각 당시 마지막 로그 항목 |

> `source`가 `"worker"`/`"ppe_violation"`/`"zone_situation"`인 항목은 `frame_path`(+`worker`/`ppe_violation`은 `bbox_xyxy`도)가 있을 수 있다 — 아래 공통 패턴 참고. `"zone_situation"`은 사람 한 명이 아니라 전체 장면 사진이라 `bbox_xyxy`는 항상 없다.

**버튼/인터랙션**

| 버튼·요소 | 누르면 일어나는 일 | [왜 필요한지] |
|---|---|---|
| 타임라인 항목 클릭 | `frame_path`가 있으면 그 순간 사진(+박스) 확대 표시 | "상태 변화"라는 텍스트만으론 부족 — 실제로 뭘 보고 그렇게 판단했는지 증거를 보여줌 |
| 타임 슬라이더 드래그(선택 구현) | 슬라이더가 멈춘 시각으로 `GET .../state-at?at=...` 호출 → 평면도·상태를 그 시각 기준으로 다시 그림 | "화재 3분 후엔 정확히 어떤 상황이었나"처럼 보고서에 쓸 특정 순간을 캡처하기 위함 |
| 소스별 필터(🔥/👤/🚧/🦺 체크박스, 선택 구현) | 타임라인에서 해당 종류만 남기고 숨김 | 로그가 길어지면 "작업자 관련만 보고 싶다" 같은 요구가 생기므로 |

## 공통 패턴 — 로그 클릭 시 증거 사진

PPE 미착용 로그, 작업자 상태변화 로그, 사고 리플레이 타임라인 모두 같은 모양의 필드(`frame_path` + `bbox_xyxy`)를 갖고 있다. 로그 한 줄을 클릭하면:

1. `frame_path`를 이미지로 띄운다(이미 있는 `frameUrl()` 헬퍼로 절대 URL 변환)
2. 그 위에 `bbox_xyxy` 박스 하나를 그린다 — **`DetectionOverlay.tsx`를 그대로 재사용 가능**하다. 지금은 `detections: Detection[]`(여러 개) 형태를 받는데, 단일 로그 항목은 `[{ object_class: entry.violations?.join(", ") ?? "확인 필요", confidence: entry.confidence ?? 1, bbox_xyxy: entry.bbox_xyxy }]`처럼 배열 하나짜리로 감싸서 그대로 넘기면 된다(`violations`는 `["helmet"]`처럼 리스트이므로 화면에 합쳐 보여줄 땐 join).

**같은 사람인지 AI가 판단해주지 않는다.** 추적 ID가 바뀌어도 로그는 그냥 새 건으로 계속 쌓이도록 설계했다(위 1번 화면의 경고 박스 참고). 화면에서도 로그를 ID로 묶거나 "동일인 추정" 같은 걸 자동으로 표시하지 말 것 — 관리자가 사진을 보고 직접 판단하는 게 이 설계의 핵심이다.

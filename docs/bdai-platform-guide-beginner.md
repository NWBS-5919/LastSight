# BDAI 플랫폼, 하나도 몰라도 되는 사용설명서

> 이 글은 코딩도 모르고 "컴퓨터 비전(CV)"이 뭔지도 처음 듣는 사람을 위한 설명서예요.
> 어려운 말이 나올 때마다 바로 옆에서 쉬운 말로 다시 설명할게요.

---

## 0. 이 플랫폼은 한마디로 뭐 하는 곳일까?

**"컴퓨터한테 사진 보는 법을 가르치는 학원"** 이라고 생각하면 돼요.

사람은 태어나서 부모님이 "이건 강아지야", "이건 고양이야" 하고 여러 번 알려주면 나중엔 혼자서도 구별할 수 있게 되죠. 컴퓨터(AI)도 똑같아요. 그런데 컴퓨터는 사진을 그냥 보여준다고 배우지 못해요. **사진마다 "여기 있는 이게 강아지야"라고 손으로 콕 집어 표시해줘야** 배울 수 있어요.

이 플랫폼이 하는 일이 정확히 그거예요.

1. 사진을 잔뜩 모으고
2. 사람이 사진마다 "이게 뭔지" 표시해주고 (이걸 **라벨링**이라고 불러요)
3. 그 표시된 사진들을 컴퓨터한테 문제집처럼 풀게 시켜서 (이걸 **학습**이라고 불러요)
4. 다 배운 컴퓨터(이걸 **모델**이라고 불러요)를 실전에 투입해서
5. 새로운 사진을 줬을 때 컴퓨터가 "이건 강아지네요!"라고 스스로 알아맞히게 만드는 것

이 전체 과정을 처음부터 끝까지 한 웹사이트 안에서 다 할 수 있게 만든 도구가 BDAI예요.

---

## 1. 헷갈리는 용어, 비유로 미리 정리하기

플랫폼 안에서 자주 보이는 단어들을 학교 준비물에 비유해서 정리해볼게요.

| 플랫폼 용어 | 쉬운 말로 하면 |
|---|---|
| **데이터셋 (Dataset)** | 사진을 모아둔 **사진첩** 한 권 |
| **에셋 (Asset)** | 사진첩 안의 **사진 한 장** |
| **프로젝트 (Project)** | 그 사진첩으로 **무엇을 가르칠지 정한 학습지 묶음**. 같은 사진첩이라도 "사람 찾기 학습지", "차 찾기 학습지"처럼 여러 개 만들 수 있어요 |
| **스키마 (Schema)** | 그 학습지의 **정답 목록** ("여기서는 사람, 자동차, 신호등만 찾으면 돼요" 같은 규칙) |
| **라벨링 (Labeling)** | 사진 위에 **정답을 직접 표시**하는 작업 (네모를 그리고 "이건 사람"이라고 붙이는 것) |
| **검수 (Review)** | 다른 사람이 **표시가 맞게 됐는지 검사**하는 것 (선생님 채점) |
| **스냅샷 (Snapshot)** | 지금까지 표시해둔 걸 **그 순간 그대로 사진 찍어서 보관**해두는 것. 나중에 표시 내용을 더 고쳐도 스냅샷은 안 바뀜 |
| **학습 (Training)** | 그 스냅샷(문제집)으로 **컴퓨터를 실제로 공부시키는 것** |
| **모델 (Model)** | **공부를 마친 컴퓨터**. 이제 새 사진을 보여주면 스스로 답할 수 있어요 |
| **배포 (Deployment)** | 다 배운 모델을 **실제로 써먹을 수 있게 전원을 켜두는 것** (가게 문을 여는 것과 비슷) |
| **자동 라벨링 (Auto-labeling)** | 다 배운 모델이 **새 사진에 미리 답을 대신 써주는 것** (사람은 맞았는지 확인만 하면 되니 훨씬 빨라짐) |
| **테넌트 (Tenant)** | 우리 팀 전체가 쓰는 **회사/동아리방** 같은 공간. 모든 사진첩·학습지가 이 공간 안에 들어있어요 |

이 순서만 기억하면 돼요:

> **사진 모으기 → 정답 표시하기(라벨링) → 검사하기(검수) → 그 순간을 저장(스냅샷) → 컴퓨터 공부시키기(학습) → 실전 투입(배포) → 컴퓨터가 대신 표시(자동 라벨링)**

이게 한 바퀴 돌면 다시 새 사진에 자동 라벨링 → 사람이 확인 → 또 학습... 이렇게 반복하면서 점점 똑똑한 AI가 만들어져요.

## 2. 역할 나누기 — 누가 뭘 하나요?

팀 프로젝트를 할 때처럼 사람마다 맡은 일이 달라요.

| 역할 | 하는 일 (쉬운 말) |
|---|---|
| **라벨러 (Labeler)** | 사진에 직접 표시(네모 그리기, 이름 붙이기)하는 사람. 학습지 푸는 사람 |
| **리뷰어 (Reviewer)** | 라벨러가 표시한 게 맞는지 검사하는 사람. 채점하는 사람 |
| **매니저 (Manager)** | 학습지(프로젝트)를 만들고, 정답 목록(스키마)을 정하고, 누가 뭘 할지 배정하는 사람. 담임 선생님 |
| **관리자 (Admin)** | 위에 있는 걸 전부 할 수 있고, 추가로 컴퓨터 공부시키기(학습)·실전 투입(배포)까지 관리하는 사람. 교장 선생님 |

혼자 프로젝트를 진행한다면 이 역할을 전부 혼자 맡게 돼요. 그래도 괜찮아요 — 순서만 따라가면 돼요.

## 3. 실제로 따라 하는 순서

### 1단계. 사진 모으기 (데이터 준비)

- **데이터셋 만들기**: 먼저 "사진첩"을 하나 만들고 이름을 정해요. (예: "공사장 안전모 사진첩")
- **업로드**: 그 사진첩에 사진 파일들을 폴더째로 끌어다 놓으면 자동으로 올라가요. 다른 화면으로 이동해도 위쪽에서 계속 업로드가 진행돼요.
- **임베딩** *(선택)*: "이 사진이랑 비슷한 사진 찾아줘" 기능을 쓰고 싶으면 눌러두는 준비 작업이에요. 안 눌러도 다른 기능은 다 쓸 수 있어요.

### 2단계. 무엇을 가르칠지 정하기 (프로젝트 구성)

- **프로젝트 만들기**: 사진첩 위에 "이번엔 이 사진들로 뭘 가르칠지" 정하는 학습지를 하나 만들어요.
- **스키마(정답 목록) 정하기**: "우리는 사람이랑 자동차만 찾을 거예요" 처럼 찾아야 할 대상 목록을 정해요. 이렇게 정해두면 라벨링할 때 딱 이 목록 안에서만 고르게 돼서 헷갈리지 않아요.
  - 참고로 찾는 방식이 두 가지예요: 사진 속 특정 물건에 네모/테두리를 그리는 방식(**객체 검출**), 그리고 사진 전체를 보고 "낮이다/밤이다"처럼 하나의 답만 고르는 방식(**분류**).
- **멤버 초대 & 담당 나누기**: 같이 할 사람을 초대하고, 누가 어떤 사진을 라벨링할지 정해요. (자기가 알아서 골라가는 방식 / 선생님이 직접 나눠주는 방식 중 선택)
- **가이드라인 작성** *(선택)*: "이런 경우엔 이렇게 표시해주세요" 같은 안내문을 써두면, 같이 하는 사람들이 헷갈리지 않아요.

### 3단계. 사진에 직접 표시하기 (라벨링)

라벨러가 되면 이런 화면을 만나요.

- **작업 큐**: 오늘 내가 할 일 목록이에요. "새로 시작할 것", "하다 만 것", "선생님이 다시 하라고 돌려보낸 것" 이렇게 나뉘어 있어요.
- **캔버스(그림판)**: 사진을 열면 그림판처럼 마우스로 표시할 수 있어요.
  - **네모(박스)**: 자동차, 표지판처럼 모양이 단순한 물건에 빠르게 네모를 그려요.
  - **테두리 따라 그리기(폴리곤)**: 모양이 복잡한 물건은 클릭클릭해서 윤곽선을 정확히 따라 그려요.
  - **AI가 도와주는 자동 윤곽(스마트 세그먼트)**: 물건을 클릭만 하면 AI가 알아서 윤곽선을 잡아줘요. 그다음 살짝 다듬기만 하면 돼요.
  - **점 찍기(키포인트) / 붓칠(브러시)**: 관절처럼 점으로 표시하거나, 경계가 흐릿한 곳은 붓으로 칠하듯 표시해요.
- **다 그렸으면 이름표 붙이기**: 그린 도형을 클릭하고 "이건 사람" "이건 자동차"처럼 정답 목록에서 골라 붙여요.
- **체크리스트 확인 후 제출**: 빠진 게 없는지 자동으로 알려주는 목록이 있어요. 다 채우면 제출! 제출하면 다음 사람(리뷰어)의 검사 대기줄로 넘어가요.

### 4단계. 검사받기 (검수)

- 리뷰어가 라벨러가 표시한 걸 보고 **"통과(승인)"** 또는 **"다시 해주세요(반려)"**로 판정해요.
- 반려되면 라벨러 화면에 "이래서 반려됐어요"라는 이유가 뜨고, 그걸 보고 다시 고쳐서 제출하면 돼요.

### 5단계. 지금까지 한 걸 사진 찍어두기 (스냅샷)

- 라벨링이 어느 정도 쌓이면 **"스냅샷"** 버튼을 눌러요. 지금까지 표시한 내용을 그 순간 그대로 저장해두는 거예요.
- 나중에 표시 내용을 더 고쳐도 이 스냅샷은 안 바뀌어요. **컴퓨터를 공부시킬 땐 항상 이 스냅샷(고정된 문제집)을 써요.**
- 왜 필요하냐면, "이번에 학습시킨 AI가 정확히 어떤 데이터로 공부했는지" 나중에 다시 확인할 수 있게 하기 위해서예요.

### 6단계. 컴퓨터 공부시키기 (모델 학습)

- 스냅샷을 골라서 **"학습 시작"** 버튼만 누르면 끝이에요. 코딩 안 해도 돼요. 컴퓨터(서버)가 알아서 그 사진과 표시 내용을 보고 공부해요.
- 공부가 끝나면 **"모델"**이라는 결과물이 생겨요. 이제 이 모델한테 새 사진을 보여주면 스스로 답을 말할 수 있어요.
- **얼마나 잘 배웠는지 확인하는 성적표(성능 지표)**도 볼 수 있어요. 어려운 용어들이 나오지만 이렇게 이해하면 돼요:
  - **정밀도**: AI가 "여기 있다!"라고 말한 것 중에서, 진짜로 맞았던 비율. (헛다리 짚은 게 적을수록 높음)
  - **재현율**: 사진 속에 진짜 있던 것 중에서, AI가 놓치지 않고 찾아낸 비율. (못 찾고 지나친 게 적을수록 높음)
  - **F1 점수**: 위 두 가지의 균형 점수. 둘 다 어느 정도 잘해야 높게 나와요.
  - **헷갈림 표(혼동 행렬)**: AI가 어떤 것을 어떤 것으로 착각했는지 정리해둔 표예요. (예: 고양이를 개로 착각한 횟수가 많다면 → 그 두 개를 구별하는 예시를 더 보강해야 함을 알려줘요)
  - 점수가 낮은 항목이 있으면 "그 종류 사진을 더 많이/더 정확하게 표시해서 보강해야겠다"는 신호로 받아들이면 돼요.

### 7단계. 실전에 써먹기 (배포·활용)

- **배포**: 다 배운 모델의 전원을 켜서, 언제든 새 사진을 보내면 답해줄 수 있는 상태로 만들어요. (가게 문을 여는 것과 같아요. 다 쓰면 꺼서 비용을 아낄 수 있어요)
- **비교/체험**: 새 사진 몇 장을 넣어보고 모델이 잘 맞히는지 눈으로 직접 확인해볼 수 있어요. 모델을 여러 개 만들었다면 나란히 비교도 가능해요.
- **자동 라벨링**: 배포한 모델이 **새로 들어온 사진에 미리 정답을 표시**해줘요. 사람은 그걸 처음부터 그리는 대신 "맞다/틀리다"만 확인하면 되니까 훨씬 빨라져요. 이렇게 만들어진 라벨을 또 검수하고, 또 스냅샷 찍고, 또 학습시키면서 AI가 점점 똑똑해져요.

### 8단계. 팀 공간 관리 (테넌트 운영) — 관리자만

- **멤버 관리**: 같이 할 팀원 초대하고 권한(라벨러/리뷰어/매니저/관리자) 정하기
- **API 키**: 나중에 개발자가 코드로 자동화하고 싶을 때 쓰는 "출입 카드" 같은 열쇠예요. 코딩 모르면 신경 안 써도 돼요
- **활동 기록**: 누가 언제 무엇을 했는지 남는 기록 (관리자만 볼 수 있어요)

## 4. 자주 헷갈리는 것 Q&A

**Q. 라벨링이랑 검수는 뭐가 다른가요?**
라벨링 = 표시하는 사람(학생), 검수 = 그걸 검사하는 사람(선생님). 같은 사진을 두고 역할이 다를 뿐이에요.

**Q. 분류(classification)랑 속성(attribute)이 헷갈려요.**
- **분류**: 사진 한 장 전체에 대한 답이에요. (예: "이 사진은 낮인가요, 밤인가요?")
- **속성**: 내가 그린 도형 하나에 딸린 세부 질문이에요. (예: 사람을 표시했다면 "이 사람은 서 있나요, 앉아 있나요?")

**Q. 왜 스냅샷을 따로 찍어야 하나요? 그냥 지금 상태로 학습하면 안 되나요?**
라벨링 작업은 계속 진행 중이라 내용이 계속 바뀌어요. 스냅샷 없이 학습하면 "정확히 어떤 데이터로 공부했는지"가 애매해져요. 스냅샷은 그 순간을 고정해서 "이 문제집으로 공부했다"를 확실하게 남기는 장치예요.

**Q. 모델 성능 점수가 낮으면 어떻게 하나요?**
대부분 "그 종류의 사진(또는 표시)이 부족하다"는 뜻이에요. 헷갈림 표에서 자주 틀리는 항목을 찾아 그 종류의 사진을 더 모으거나, 표시를 더 꼼꼼히 다시 하면 점수가 올라가요.

**Q. 코딩을 몰라도 이 플랫폼을 처음부터 끝까지 다 쓸 수 있나요?**
네, 가능해요. 이 문서에서 설명한 모든 단계(업로드, 라벨링, 검수, 스냅샷, 학습, 배포, 자동 라벨링)는 전부 마우스 클릭만으로 웹 화면에서 할 수 있어요. 코딩(SDK)은 이걸 나중에 자동화하고 싶은 사람을 위한 "선택 사항"일 뿐이에요.

## 5. 한눈에 보는 전체 그림
